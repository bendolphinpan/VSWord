## §1 · CSP 静态扫描（PRD §8 T-3.5b-seq.1 step 1）

命令：
```
grep -cE 'new Function\(|\bFunction\s*\(|\beval\s*\(|document\.write' \
  node_modules/@rokt33r/js-sequence-diagrams/dist/*.js \
  node_modules/raphael/*.js \
  node_modules/underscore/*.js
```

原始输出（每列：`newFn / Fn( / eval / document.write`）：

| 产物 | 大小 | newFn | Fn( | eval | doc.write |
|------|------|-------|-----|------|-----------|
| `dist/sequence-diagram.js` | 132,095 | 0 | 0 | 0 | 0 |
| `dist/sequence-diagram-min.js` | 89,797 | 0 | 0 | 0 | 0 |
| `dist/sequence-diagram-raphael.js` | 123,243 | 0 | 0 | 0 | 0 |
| `dist/sequence-diagram-raphael-min.js` | 84,994 | 0 | 0 | 0 | 0 |
| `dist/sequence-diagram-snap.js` | 55,395 | 0 | 0 | 0 | 0 |
| `raphael/raphael.js` | 310,628 | 0 | 0 | 0 | 0 |
| `raphael/raphael.min.js` | 93,167 | 0 | 0 | 0 | 0 |
| `raphael/raphael.no-deps.js` | 295,398 | 0 | 0 | 0 | 0 |
| **`underscore/underscore.js`** | 41,417 | **1** | **2** | 0 | 0 |
| **`underscore/underscore-min.js`** | 13,450 | 0 | **1** | 0 | 0 |

**关键辨析**：underscore 1.4 里 `new Function` 唯一现身处在 `_.template()` 定义体内（`underscore.js:1156`）。sequence-diagram 静态引用的 underscore API 只有 `_.bind / _.defaults / _.each / _.every / _.extend / _.getFont / _.height / _.isArray / _.isEmpty / _.isFinite / _.isString / _.line / _.obj / _.path / _.print / _.rect / _.setFinish / _.setSize / _.setStart / _.text`，**不包含 `_.template`**。CSP 只在运行到 `new Function()` 时才拦截；库源码里 dead-code 存在不构成 violation。

**Fork parser 类型澄清**：sequence-diagram dist 里有明确注释 `/* parser generated by jison 0.4.15 */`（`sequence-diagram.js:142`）。jison 是 LALR/LL parser generator，**输出静态跳转表 + 普通函数**，不使用 `new Function()`。PRD §9 R-1 里"PEG.js 生成的 parser 使用 `new Function()`"这个假设**基于对上游包源码的推测**，实际 rokt33r fork 从未用过 PEG.js。

### §1 决策点（PRD 原文）
> - 若 chunk 里无 `new Function` → go
> - 若有 → 走 vendor + `pegjs --format globals` 预编译方案

→ **命中"go"分支**。step 2（预编译兜底方案）**不执行**。

## §2 · Fixture 渲染验证（PRD §8 T-3.5b-seq.1 step 3）

### 2.1 jsdom 语法层验证

`run-jsdom.mjs` 加载 `demo.html`，用 UMD 三段脚本 + `Diagram.parse` + `drawSVG`。首次 parse 用错语法关键字（`Actor` / `Title`），jison 抛 `Expecting ',', 'LINE', 'DOTLINE', 'MESSAGE', got 'NL'` —— 说明 parser 正常工作。改用官方 `participant` / `title` 后 parse 通过，`drawSVG` 阶段被 jsdom 卡在 `cnvs.createSVGMatrix is not a function`（jsdom SVG 后端短板，与被测库无关）。

### 2.2 Playwright chromium · 严格 CSP

`demo-csp.html` 头部：
```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'none'; script-src 'self' 'nonce-spike';
               style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:;
               font-src 'self' data:; connect-src 'self';">
```

`run-chromium-csp.mjs` 结果：
```json
{
  "outText": "OK · svg outerHTML length = 5857",
  "hasSvg": true,
  "svgOuterLength": 5857,
  "cspViolationCount": 0,
  "cspSample": [],
  "logCount": 0
}
```

SVG 元素结构（节选自 `chromium-csp-output.svg`）：
- `<svg width="160" height="276">`
- `<desc>Created with Raphaël 2.3.0</desc>` ← raphael 2.3.0 兼容性证据
- title 框 · 两个 participant 框（A / B · 上下两组）· 生命线 · sync 箭头 · async 虚线箭头 · Note 框
- P0 全部四种句法元素齐备

### 2.3 Playwright chromium · 无 CSP 对照（含 window.Function/eval 运行时探针）

`run-chromium.mjs` 用 Proxy 拦截 `window.Function` 构造与 `window.eval` 调用：
```json
{
  "svgOuterLength": 5857,
  "fnCtorCount": 0,   // ← 全流程 0 次 new Function / Function.apply
  "evalCount": 3,      // ← 全部为 playwright 自身注入探针（"el => el.outerHTML" 等）
  "hitsSample": [
    {"k":"eval","code":"el => el.outerHTML"},
    {"k":"eval","code":"(injected, e) => \"JSHandle@\" + injected.previewNode(e)"},
    {"k":"eval","code":"() => ({\\n  fnCtorCount: window.__spike.fnCtorCount..."}
  ]
}
```

3 次 eval 是 playwright 通过 CDP 注入的探针函数，**不来自被测库**。**结论：sequence + raphael + underscore 组合在 render 全流程中运行时 0 次触发 `new Function` / `eval`**。

## §5 · 对 PRD 的建议修订

Spike 结果与 PRD v1.1 有 5 处偏差，建议在下一版（v1.2）里更新：

1. **§9 R-1（首要风险）**：删除或降级。改写为：
   > R-1（历史假设已排除）：rokt33r fork 由 jison 0.4.15 生成 parser，dist 三产物 0 处 `new Function()` / `eval` / `document.write`，Playwright 严格 CSP 验证 0 violation。原 PEG.js 阻塞担忧不适用。

2. **§7 C-2 · sequence 分支**：删除关于 PEG.js 与预编译 vendor 方案的整段（"js-sequence-diagrams：其 parser 由 PEG.js 生成…必须验证… 若未预编译，需构建时 vendor 一份编译产物…"），改为一句：
   > js-sequence-diagrams：fork 已用 jison 预编译 parser 为静态跳转表 + 普通函数，dist 直接可 npm 引用，无需 vendor 化。

3. **§11 Q2**：题目本身可作废（"CSP 阻塞兜底路径"不再有实际触发条件）。若保留题目留档，答案已实证为 Q2=a 且**无需真正投入预编译工作**。

4. **§4 Bundle 预估**：sequence chunk 从"60-90 KB gzip"更新为"约 35 KB gzip"（含 underscore，raphael 走共享）。首个 sequence 图加载总成本约 67 KB gzip。

5. **§10 D-11（若有关于 vendor 化的假设）**：删除 sequence 侧的 vendor 化预留（保留 flow 侧留待 T-3.5b-flow.1 结论）。
