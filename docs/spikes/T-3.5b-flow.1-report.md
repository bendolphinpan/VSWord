### R-2 · Raphael VML 分支排查

Raphael 内 VML 相关代码在浏览器不支持 SVG（旧 IE）时启用，Chromium webview 一定走 SVG 分支，VML 分支是运行时 dead code。静态特征命中数：

| 特征 | 命中次数 |
|---|---|
| `R.vml` 关键字（含赋值与读取） | 3 |
| `createStyleSheet` 调用 | 1 |
| `VML` 字面串（含注释） | 11 |

关键分支入口在 `raphael.js:449`：

```js
R.type = (g.win.SVGAngle
          || g.doc.implementation.hasFeature("http://www.w3.org/TR/SVG11/feature#BasicStructure", "1.1")
          ? "SVG" : "VML");
R.svg   = !(R.vml = R.type == "VML");
```

Chromium webview 中 `SVGAngle` 存在 → `R.type = "SVG"` → 所有 `if (R.vml)` 分支不进入。**不影响 CSP，仅影响 bundle 体积**。

### R-2 的构建时剔除尝试

试过 esbuild `define: { RAPHAEL_HAS_VML: 'false' }`，无效果——Raphael 走的是运行时判断（`g.win.SVGAngle`），define 无法从 UMD 里静态删掉 VML 代码路径。想彻底剪掉 VML 分支需手工 patch（`raphael.no-deps.js` 里删掉 `if (R.type == "VML")` 至匹配 `}`），预估可再省 ~10-15KB min（~3-5KB gzip）。**放到 flow.2 收尾阶段再考虑做**，spike 不实施。

## 4. Bundle 尺寸实测（验证 PRD §7 预估）

用 esbuild 0.24.0 `--bundle --minify --format=iife`。

| Bundle | 组成 | min | gzip@9 |
|---|---|---:|---:|
| `flowchart-standalone` | flowchart.js + raphael 全打 | **127.4 KB** | **40.9 KB** |
| `raphael` | Raphael 单独 chunk | 92.7 KB | 32.8 KB |
| `flowchart`（external raphael） | 只含 flowchart.js（raphael 走共享 chunk） | **35.1 KB** | **8.5 KB** |
| 官方 `raphael.min.js`（对照） | 未经二次打包 | 91.0 KB | 31.5 KB |
| 官方 `raphael.no-deps.min.js`（对照） | 无 eve 依赖版 | 88.1 KB | 30.5 KB |

**对齐 PRD §7 预估**：

- PRD 预估：flowchart chunk ≈ 110–130 KB + raphael 走共享 chunk。
- 实测 standalone min=127.4 KB → **落在 PRD 上限**，符合预期。
- 拆共享 chunk 后 flowchart 独立 chunk 只需 8.5 KB gzip（比预估好很多），因为它本身只是解析器 + 符号定义，绝大部分体积来自 raphael。

**结论：验证 PRD 预估准确，且拆共享 chunk 收益显著（flowchart chunk 从 40.9KB gz → 8.5KB gz）**，AC-8 "raphael 共享 chunk" 目标在实现层是可行的。

```jsonc
{
  "overrides": {
```

## 6. Raphael Chunk 拆分方案（不实施，只出结论）

参考 `.tmp/milkdown-prod-builder/` 里 mermaid chunk 的拆分做法：

```js
// build-milkdown-editor.cjs 里 flowchart 独立 entry 的 esbuild 配置片段
await build({
  entryPoints: ['./editor/nodeviews/flowchart/flowchart.chunk.js'],
  bundle: true,
  minify: true,
  format: 'iife',
  globalName: 'vswordFlowchart',
  outfile: 'out/webview/flowchart.chunk.js',
  external: ['./raphael.chunk.js'], // 或用 alias
  // Raphael 通过 window.Raphael 复用同一份实例
  banner: { js: 'var Raphael = window.__vswordRaphael;' },
});

// raphael 独立 entry
await build({
  entryPoints: ['./editor/vendor/raphael-entry.js'], // 内容：window.__vswordRaphael = require('raphael');
  bundle: true,
  minify: true,
  format: 'iife',
  outfile: 'out/webview/raphael.chunk.js',
});

// 同理 sequence.chunk.js external raphael，从 window.__vswordRaphael 拿
```

`flowchart-view.template.js` 里用动态 import 拉两个 chunk：

```js
async function loadFlowchartRuntime() {
  if (!window.__vswordRaphael) {
    await import(/* @vite-ignore */ './raphael.chunk.js');
  }
  if (!window.__vswordFlowchart) {
    await import(/* @vite-ignore */ './flowchart.chunk.js');
  }
  return window.flowchart;
}
```

AC-8 里 "打开纯文本 md 不加载三个 chunk / 打开含 flow 的加载 raphael+flowchart / 打开含 sequence 且 raphael 已缓存" 的语义就用上面这个动态 import 结构实现。**mirror mermaid pattern，不需要新技术栈**。

## 7. 已发现的实施细节 / 给 flow.2 的注意事项

1. **Raphael 检测 SVG 靠 `SVGAngle` 或 `hasFeature`**：Chromium 都有，不用挂 shim。jsdom 单测里要挂（本次 probe 里已做）。
2. **flowchart.js 从 `require('raphael')` 拿构造器**，也从 `window.Raphael` 读——共享 chunk 场景下必须两条路径都能返回同一份实例。用 esbuild banner 或 `window.__vswordRaphael` 桥接即可。
3. **CSP `style-src`**：flowchart.js 会 `svg.style.xxx = ...` inline 写样式（无 `<style>`）；raphael 也仅用 inline SVG 属性，不注入 `<style>` 节点。webview 现有 `style-src 'self' 'unsafe-inline'` 足够。**不需要 nonce**。
4. **`user-select` / `pointer-events`**：flowchart.js 生成的 SVG 默认无 pointer-events 拦截，NodeView 里包一层 `<div>` 拦截点击就能进 T-3.5b-flow.2 的编辑态。
5. **主题联动（AC-7）**：Raphael 无内部主题机制，颜色靠 flowchart options 传（`fill` / `stroke` / `font-color`）。redraw 只需重新 `parse().drawSVG()`，无需 patch runtime；参照 mermaid-view 的 theme bridge。
6. **VML 剩余体积**：如需再挤 3–5KB gz，可在 flow.2 收尾阶段手工 patch `raphael.no-deps.js` 删 VML 分支。不建议 spike 阶段做。
7. **`enterprise CSP` 变体**：若未来切到 `strict-dynamic` + hash，raphael/flowchart 生成的都是 DOM 操作，无 `<script>` 动态注入，兼容性不变。
