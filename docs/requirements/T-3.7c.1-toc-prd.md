## 0. 目标与非目标

### 0.1 目标（Goals）

- 支持 Typora 语法 `[TOC]` 占位符：markdown 源码里的 `[TOC]` 段落在 WYSIWYG 视图渲染为**多级目录**（H1–H6 heading 树）。
- 目录条目**点击 → 光标 / 视口跳转到对应 heading**（realtime + reading 两种模式都通）。
- 文档 heading 增删改后，TOC **自动重算**（同一 doc 事务内 update）。
- **Round-trip 保真**：`[TOC]` → editor → markdown 字节完全一致（Gate F 通过）。
- 满足 master plan §UI 重构接口预留 4 项强制要求（命令化 / 状态服务化 N/A / 消息协议 N/A / UI 组件契约）。
- 与 Phase 3 现有能力（Round-trip Gate E · Mermaid/flow/seq Gate F · 双链 · outline 面板 · 视图模式）**零回归**。

### 0.2 非目标（Non-Goals · Phase 3 后置）

- ⛔ **主题 / 视觉调优**（TOC 字号 / 缩进像素 / 悬浮态 / 分割线）——统一放到 Phase 3 末的 UI 布局阶段
- ⛔ **交互式重排 TOC**（拖拽调节 heading 层级 / 折叠子树 / 隐藏某级）——`outline` 侧边面板已提供，本 PRD 不重复
- ⛔ **配置化 TOC 深度 / 最大 heading level**（例如 `[TOC:2]` 只到 H2）——保留默认 H1–H6 全展开，后续如有需求单独 ADR
- ⛔ **`[[toc]]` / `${toc}` / `<!-- TOC -->` 等其他生态变体**——本 PRD 只认 Typora 标准 `[TOC]`（大小写不敏感见 §2.5）
- ⛔ **GitHub `remark-toc` 语义**（匹配 "Table of contents" heading 下方自动插入）——与 Typora 语义不同，不做
- ⛔ **导出/打印视图里 TOC 的分页锚 / 页码**（Phase 3 后置到 T-3.8b 导出层）
- ⛔ **outline 侧边面板本身**（属 T-3.7c.2，已由 `9f76d3e0` 交付；本 PRD 只复用其 slugify 逻辑，不改代码）

### 1.2 关键差别（TOC vs 其他 NodeView）

| 维度 | mermaid/flow/seq NodeView | 数学 NodeView | **TOC NodeView（本 PRD）** |
|---|---|---|---|
| 数据源 | 节点自身 attrs.code | 节点自身 attrs.value | **全 doc heading 树**（跨节点依赖） |

**关键约束**：TOC 是**跨节点依赖**，必须在 doc 事务级捕获 heading 变更（appendTransaction）并触发所有活着的 TOC NodeView 重算。

## 2. 用户故事 / 交互流

### 2.1 US-1 · 插入并查看目录

> **As a** 中文写作者
> **I want** 在 markdown 里任意位置写 `[TOC]` 就自动出现目录
> **So that** 长文档能一眼看到结构 · 不用手工维护目录

**入口**：
- 直接键入：markdown 源码里独立段落 `[TOC]` → 实时渲染出目录
- 快捷命令（可选，见 §4.1）：命令面板 `VSWord 目录: 在光标处插入 [TOC]` → 插入 `[TOC]\n\n` 到光标位置

**视觉反馈**：
- 渲染为 `<nav class="vsword-toc" contenteditable="false">` 容器
- 内嵌嵌套 `<ol class="vsword-toc-list vsword-toc-level-N">` × N（N = 出现的 heading level 层数）
- 每条目 `<li><a href="#<slug>" data-heading-pos="<pos>">标题文本</a></li>`
- **视觉延后**：Phase 3 只保证列表可读（默认 UA 样式 + 极小 tweak），字号/间距/悬浮态放 UI 布局阶段

### 2.2 US-2 · 点击跳转

> **As a** 中文写作者
> **I want** 点击 TOC 条目跳到对应 heading
> **So that** 长文导航不用滚半天

**行为**：
- realtime / reading 模式点击：**光标定位到 heading 首字符位置 + `EditorView.scrollIntoView`**
- source 模式：TOC 不渲染（textarea 里就是 raw `[TOC]` 文本），点击无意义
- 快捷键：**无**（Phase 3 不额外分配；命令面板/直接点击已够用）

### 2.3 US-3 · heading 变更自动重算

> **As a** 中文写作者
> **I want** 我改了标题文字/加了新 H2/删了某 H3 → TOC 立刻同步
> **So that** 不用手动刷新

**行为**：
- 每次 doc transaction 结束后，若本次事务 `docChanged` 且新旧 doc 的 heading 序列 shallow-hash 不同 → 通知所有活着的 TOC NodeView 重算
- 单文档 heading 数 ≤ 500 时，重算耗时 ≤ 5ms（P95 目标；见 §5 perf）

### 2.4 US-4 · 空目录 / 无 heading

> **As a** 用户
> **I want** 空文档 + `[TOC]` 不炸
> **So that** 编辑体验稳定

**行为**：
- 无 heading → TOC 容器渲染中文占位 `<p class="vsword-toc-empty">（暂无标题）</p>`
- 未来 heading 加入 → 占位消失 → 目录树出现（走 US-3 重算路径）

### 2.5 US-5 · 边缘输入

> **As a** 迁移 Typora 老文档的用户
> **I want** `[TOC]` 各种大小写 / 前后空白 / 相邻文本都能正确识别或明确拒识
> **So that** 与 Typora 行为对齐

**匹配规则**（默认 a · 与 Typora 参照对齐）：

| 输入 | 识别为 TOC？ | 备注 |
|---|---|---|
| `[TOC]` 独占段落 | ✅ | 标准 |
| `[toc]` / `[Toc]` / `[TOC ]` | ✅ | 大小写不敏感 + trailing 空白允许 |
| ` [TOC]`（首行前 1-3 空格） | ✅ | 允许 ≤ 3 前导空格（GFM paragraph 允许） |
| `[TOC] extra text` | ❌ | 有额外文本 → 普通 paragraph，不识别 |
| `` `[TOC]` ``（code span） | ❌ | 代码字面量，不识别 |
| ` ```\n[TOC]\n``` `（代码块内） | ❌ | 代码块内不识别 |
| `> [TOC]`（引用块内） | ❌ | 引用块内不识别（Typora 也不识别） |
| 一份文档多个 `[TOC]` | ✅ 全部渲染 | 每处独立 NodeView 实例，共享同一 heading 数据源 |

**决策记录**：以上匹配规则整理为 ADR（§8 附录），落 `docs/decisions/0002-toc-typora-matching-rules.md`。

## 4. 技术方案

### 4.1 命令化（新增 · 强制项）

在 host 侧 `milkdownEditorContribution.ts`（或新建 `viewMode` 目录同款 `toc/vswordTocActions.ts`）用 `registerAction2` 注册：

| Action id | 标题 | 快捷键 | 参数 |
|---|---|---|---|
| `vsword.toc.insertToc` | VSWord 目录: 在光标处插入 [TOC] | — | — |

**行为**：向活跃 webview 发新消息 `insertTocAtCursor`（见 §4.3），webview 内 `editor.action((ctx) => …)` 用 ProseMirror `tr.insertText('[TOC]\n')` 在当前 selection 处插入独立段落。

**当前 PR 不做**：`vsword.toc.refresh`（无必要 · 自动重算已覆盖）· `vsword.toc.gotoHeading`（走点击即可）。

### 4.2 状态服务化（不需要 · N/A）

TOC 是纯 view 层：数据源 = 当前 doc heading 树（每次事务派生），无 preference / 无 storage / 无跨会话状态。**不引入 service**。

### 4.3 消息协议（新增一条 · host → webview）

`milkdownEditorProtocol.ts` **新增**：

```typescript
export interface InsertTocAtCursorMessage {
  type: 'insertTocAtCursor';
}
```

- 方向：host → webview
- 触发方：`vsword.toc.insertToc` Action2
- webview 处理：在 mode !== 'source' 时，`view.dispatch(tr.insertText('[TOC]\n\n'))`；source 模式时忽略（或在 textarea 里 insertText，可选）

**当前 PR 不做**：webview → host 反向消息（TOC 内部跳转全在 webview 完成，host 不参与）。

### 4.4 remark 层（新增 · 自建轻量插件）

**决策 · 默认 a**：**自建轻量 remark 插件**，不引第三方依赖。

**理由**：
- `remark-toc` 语义与 Typora 不同（匹配 "Table of contents" heading，非 `[TOC]` 占位符）
- `@retorquere/remark-toc-typora` 是社区 fork · Milkdown 生态未验证兼容性 · 且它主动生成 list AST（本 PRD 反而希望保留 `tocNode` 占位符不展开，展开延后到 NodeView 层）
- 自建插件成本 ≤ 80 行，与 `remarkLiftImgHtmlPlugin`（现存 remark 转换器）套路一致

**新增文件**：`webview/toc-remark.template.js`

**AST 转换**（`micromark-extension` 层免了，走 mdast pass）：

- 输入：mdast tree
- 遍历所有 `paragraph` 节点：若 children.length === 1 且 children[0].type === 'text' 且 `text.value.match(/^\s{0,3}\[toc\]\s*$/i)` → 替换为 `{ type: 'tocMarker', position }` 自定义节点
- 输出：mdast tree 含 tocMarker 节点

**Milkdown schema 侧**：新增 `tocNode` prosemirror node

```javascript
// webview/toc-node.template.js（新增）
export const tocNode = $node('toc_marker', () => ({
  group: 'block',
  atom: true,
  selectable: false,
  parseDOM: [{ tag: 'nav.vsword-toc' }],
  toDOM: () => ['nav', { class: 'vsword-toc', 'data-toc': 'placeholder' }, 0],
  parseMarkdown: {
    match: (node) => node.type === 'tocMarker',
    runner: (state, _node, type) => { state.addNode(type); },
  },
  toMarkdown: {
    match: (node) => node.type.name === 'toc_marker',
    // 关键：写回原样占位符 · Gate F 字节一致
    runner: (state, _node) => { state.addNode('text', undefined, { value: '[TOC]' }); state.closeBlock(_node); },
  },
}));
```

（伪代码 · dev 实施时按 Milkdown 6.x `$node` 帮手 API 校准）

### 4.5 Milkdown NodeView + 事务级监听（新增）

**新增文件**：`webview/toc-view.template.js`

**NodeView 契约**（对齐 T-3.7b.d `IMilkdownUIComponent`）：

```javascript
export function createTocNodeView(node, view, getPos) {
  const doc = view.dom.ownerDocument;
  const dom = doc.createElement('nav');
  dom.className = 'vsword-toc';
  dom.setAttribute('contenteditable', 'false');
  dom.dataset.tocInstance = String(nextInstanceId++);

  const render = () => {
    const headings = extractHeadings(view.state.doc); // 复用 outline-extractor
    dom.replaceChildren(buildTocDom(doc, headings, view));
  };
  render();

  return {
    dom,
    ignoreMutation: () => true,
    stopEvent: () => false, // 允许 click 冒到 <a>
    update: (updatedNode) => updatedNode.type.name === 'toc_marker',
    destroy: () => { /* unsubscribe from tocEventBus */ },
    _rerender: render, // 事件总线调用点
  };
}
```

**事务级监听 plugin**（新增或复用 tracker）：

```javascript
new Plugin({
  key: new PluginKey('vsword-toc-recompute'),
  appendTransaction(trs, oldState, newState) {
    if (!trs.some((tr) => tr.docChanged)) return null;
    if (!headingSequenceChanged(oldState.doc, newState.doc)) return null;
    // 广播给所有 live TOC NodeView 实例
    for (const view of liveTocViews) view._rerender();
    return null;
  },
});
```

**heading 序列 shallow-hash**：`extractHeadings(doc).map((h) => `${h.level}|${h.text}`).join('\n')` · 哈希前后不等则重算

### 4.6 点击跳转（新增）

TOC NodeView 内 `<a href="#…" data-heading-pos="<pos>">` 全局 click delegation：

```javascript
dom.addEventListener('click', (e) => {
  const a = e.target?.closest?.('a[data-heading-pos]');
  if (!a) return;
  e.preventDefault();
  const pos = Number(a.dataset.headingPos);
  if (!Number.isFinite(pos)) return;
  const tr = view.state.tr.setSelection(TextSelection.near(view.state.doc.resolve(pos + 1)));
  view.dispatch(tr.scrollIntoView());
  view.focus();
});
```

- realtime：光标定位 heading 首字符
- reading：`editable=false` 阻挡实际编辑；scrollIntoView + 视觉高亮 heading（可选：`Decoration.node` 300ms 高亮，视觉延后 · 本 PR 只做 scrollIntoView + 光标 · 高亮延后到 UI 布局阶段）

### 4.7 UI 组件契约（新增 · 强制项）

TOC NodeView 实现 `IMilkdownUIComponent`（`el` = `dom` · `mount` = 已由 NodeView 生命周期挂载 · `unmount` = destroy · `dispose` = 移除事件订阅），复用 T-3.7b.d 抽出的 contract。**不新建 component 工厂**（每实例即一个 component，由 NodeView 生命周期驱动）。

### 4.8 与 Round-trip / 其他 NodeView 的隔离

- **Round-trip**：`toc_marker` → mdast `tocMarker` → 原样 `[TOC]`（`toMarkdown` runner 保证）；Gate E 6 测无影响（TOC 节点在 roundtrip session build 里被视为一个 atom block）
- **Mermaid / flow / seq**：TOC 不影响这三类 NodeView 的 stopEvent / ignoreMutation 行为
- **outline 面板（T-3.7c.2）**：outline extractor 只看 heading 节点，不看 `toc_marker`，天然隔离
- **视图模式（T-3.7b）**：source 模式 CSS `[data-mode="source"] .vsword-toc { display: none }`（webview shell 已管 textarea 显示） · reading 模式点击行为退化到 scrollIntoView（无光标）

## 5. 验收标准（DoD · Given/When/Then）

### AC-1 · `[TOC]` 识别与渲染

> **Given** 一份文档含独立段落 `[TOC]` 和 3 个 heading（H1/H2/H3）
> **When** 文档在 realtime 模式打开
> **Then** `[TOC]` 位置渲染为 `<nav class="vsword-toc">`，含 3 个 `<li>`，文本与 heading 一致，`href` 与 slug 一致，`data-heading-pos` 与 ProseMirror pos 一致

### AC-2 · 大小写与前导空白（US-5 全表）

> **Given** 五种输入变体（见 §2.5 表）
> **When** 文档打开
> **Then** ✅ 行渲染为 TOC · ❌ 行按普通 paragraph / code / blockquote 渲染 · **无假阳性、无假阴性**
> **验收**：新增测试文件 `test/node/tocRemark.test.ts`，覆盖 §2.5 表所有 8 行 case

### AC-3 · 自动重算

> **Given** 文档已渲染 TOC
> **When** 用户新增 / 删除 / 修改 任一 heading
> **Then** TOC 在同一 doc 事务内更新，视觉上无 flicker；heading 序列 shallow-hash 未变时**不触发 DOM 变更**（防止 recompute 抖动）
> **验收**：新增单测覆盖 3 种编辑操作 + 1 种无关编辑（只改段落不改 heading，断言 TOC DOM 未 replaceChildren）

### AC-4 · 点击跳转

> **Given** TOC 已渲染
> **When** 用户点击某条目
> **Then** 光标定位到对应 heading 首字符位置（`view.state.selection.head === heading.pos + 1`），editor scrolled into view；reading 模式下 selection 依然产生但 `editable=false` 阻挡编辑

### AC-5 · Round-trip 字节一致（Gate F 扩展）

> **Given** 3 个 P0 fixture：`toc-basic.md`（单 TOC + 3 heading）· `toc-nested.md`（单 TOC + H1..H3 混合）· `toc-empty.md`（单 TOC 无 heading）
> **When** open → save → reopen → save
> **Then** 每份 fixture 的 markdown 字节前后完全一致；`[TOC]` 原样写回，无被展开为 list 的痕迹
> **验收**：新增 `test/fixtures/toc/<id>.md` + `_index.mjs`；新增 `test/node/tocRoundtrip.test.ts`（≥ 3 case + 1 元测试 = 4 case）
> **Gate F 更新**：`gate-f.mjs` 追加 TOC fixture 分类到矩阵表；总测试数从 81 case → 85+ case

### AC-6 · 与视图模式组合（T-1..T-8）

> **Given** §3 组合矩阵每条起始状态
> **When** 触发对应操作（切模式 / 加 heading / 双链 heading 等）
> **Then** 命中矩阵「行为」列
> **验收**：新增 `test/node/tocViewModeInterop.test.ts` ≥ 6 case

### AC-7 · 空目录占位

> **Given** 空文档 + `[TOC]`
> **When** 打开
> **Then** 渲染 `<p class="vsword-toc-empty">（暂无标题）</p>`
> **When** 用户添加第一个 heading
> **Then** 占位消失 · 目录 `<li>` 出现（AC-3 复用）

### AC-8 · Gate 无回归

> - Gate D（tsc 全项目 0 error · `NODE_OPTIONS=--max-old-space-size=8192 tsc --noEmit -p src/tsconfig.json`）
> - Gate E（roundtrip 6 测 252 case 全绿 · TOC 节点不破坏 session build）

## 7. 无方向性决策 · 默认 a 汇总

| # | 决策点 | 默认 a（本 PRD 采用） | 备用（未采用） |
|---|---|---|---|
| D-1 | remark 方案选型 | **自建轻量 remark 插件**（≤ 80 行 mdast 遍历） | `@retorquere/remark-toc-typora`（第三方 fork 未验证） / `remark-toc`（语义不匹配） |
| D-2 | 空 heading 处理 | **渲染 `<p class="vsword-toc-empty">（暂无标题）</p>`** | 空 `<nav>` 兜底 / 完全不渲染 |
| D-3 | 多 `[TOC]` 行为 | **全部渲染 · 共享同一 heading 数据源** | 只渲染第一个 / 排重 |
| D-4 | heading id slug 规则 | **复用 `outline-extractor.template.js#slugify`**（GitHub 风格 + CJK 保留 + `-N` 重名后缀） | 自建 slug 规则 |
| D-5 | 大小写 / 前缀空白匹配 | **大小写不敏感 + 允许 ≤ 3 前导空格 + 允许 trailing 空白** | 只识别精确 `[TOC]` |
| D-6 | 引用块 / 代码块内 `[TOC]` | **不识别**（与 Typora 一致） | 识别 / 部分识别 |
| D-7 | TOC 深度控制 | **默认 H1–H6 全展开，无深度配置** | 支持 `[TOC:2]` / config 选项 |
| D-8 | 点击跳转视觉高亮 | **只 scrollIntoView + 光标 · 无 300ms 高亮** | 加 `Decoration.node` 高亮（延后到 UI 布局阶段） |
| D-9 | 快捷键 | **无**（命令面板 + 键盘输入 `[TOC]` 已够） | 分配 `Ctrl+Shift+O`（与 outline 面板冲突） |
| D-10 | source 模式行为 | **完全不渲染 · textarea 显示 raw** | source 模式内也用轻量目录侧栏（超出本 PR） |
| D-11 | Round-trip 序列化格式 | **原样 `[TOC]`** | 展开为 markdown list（破坏 Typora 兼容） |
| D-12 | UI 组件契约实施粒度 | **NodeView 生命周期即 component** · 不新建工厂 | 抽 `createTocComponent(root)` 工厂（无收益，过度设计） |

## 8. 风险与自救

| 风险 | 触发 | 自救 |
|---|---|---|
| 事务监听导致的 O(N × doc-size) 性能塌方 | 每个 TOC NodeView 各自订阅 EditorView 事件 | 强制走单 prosemirror Plugin appendTransaction 集中广播（§4.5）；单测覆盖多 TOC 场景 |
| heading shallow-hash 判等太严 | 用户改一个空格 heading 也重算 | hash 用 `text.trim() · level` 组合，忽略首尾空白但保留内部差异 |
| toMarkdown 写回多余换行 | Milkdown `$node` runner 边界 | `_index.mjs` 里 fixture 用 `[TOC]\n\n<后续段落>` 保证 round-trip 覆盖前后 block boundary；Gate F 字节一致断言兜底 |
| 大文档 heading 序列变化 → 全 TOC 重算引发 flicker | 目录规模 > 200 条 | Phase 3 不做 diff-patch DOM（延后）· 单文档 heading ≤ 500 时目标 5ms P95；> 500 场景加 warn log |
| Typora 兼容 corner case（HTML `<a name>` 锚 / setext heading / trailing 井号变体） | 部分 Typora 用户历史文档 | slugify 现状已过 T-3.11.4 baseline 清理，直接沿用；本 PR 不新增 HTML 锚兼容 |
| Gate F fixture 冲突 | 新加 toc 分类占用现有 mermaid/flow/seq worker | fixture 目录独立 `test/fixtures/toc/` · gate-f.mjs 只追加分类不改现有 selfcheck 通道 |
| tsc 循环依赖 | protocol 新增 message + Action2 引入 view mode service（虽然不共享类型） | 新 message 类型独立 export，Action2 侧只 import type，避免运行时循环 |
