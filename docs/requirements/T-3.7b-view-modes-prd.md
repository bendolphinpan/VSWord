## 0. 目标与非目标

### 0.1 目标（Goals）

- 4 种视图子模式全部落地，每一种都可通过 **快捷键 / 命令面板 / 工具栏按钮** 三条入口触发，行为一致。
- 每一种模式都满足 master plan §UI 重构接口预留 4 项强制要求（命令化 / 状态服务化 / 消息协议 / UI 组件契约）。
- 4 种模式的组合矩阵形成**规则表**并被单测覆盖，禁止歧义组合。
- 与 Phase 3 现有能力（Round-trip 保真、Mermaid/flow/seq NodeView、双链、outline）**零回归**。

### 0.2 非目标（Non-Goals · Phase 3 后置）

- ⛔ **主题 / 视觉调优**（配色、留白、字号、动画过渡）——统一放到 Phase 3 末的 UI 布局阶段
- ⛔ 阅读模式的 "打印视图 / 排版预设"（放到 T-3.7d 主题层）
- ⛔ 源码模式的 Monaco 语法高亮增强（现状 `<textarea>` 即可）
- ⛔ 打字机模式的滚动动画曲线可配置项（Phase 3 只做默认体验）
- ⛔ 视图模式在 outline / 双链面板等**外部视图**中的联动（本 PRD 只管编辑器内）

## 2. 用户故事 / 交互流

### 2.1 US-1 源码模式（3.7b.1）

> **As a** 中文写作者
> **I want** 一键切到源码模式看到 raw markdown
> **So that** 我可以直接改标记（如 HTML 块、复杂表格、frontmatter）

**入口**：
- 快捷键 `Ctrl+/` 循环切换（realtime → reading → source → realtime）
- 快捷键 `Ctrl+Shift+M S`（source 独立锁定，可选）
- 命令面板 `VSWord 视图模式: 切换源码模式`
- 工具栏 mode-switch 按钮组「源码模式」

**视觉反馈**：
- shell attribute `data-mode="source"`
- textarea 获得焦点（现状：`requestAnimationFrame(() => sourceTextarea.focus())`）
- 工具栏 focus/typewriter 按钮进入 disabled 态

**退出条件**：
- 再次按 `Ctrl+/` 循环回 realtime
- 命令面板切走
- 用户手动点其他 mode 按钮
- 退出时把 textarea 内容 `setMarkdown(v, 'source-exit')` 回填（现状已实现）

**次级入口**：webview 右上角「以文本编辑器打开」按钮 → 发 `openAsText` → host 端 `openAsText` 走 VS Code 原生 text editor 替换（现状已实现，本 PRD 不改）

### 2.2 US-2 阅读模式（3.7b.2）

> **As a** 中文写作者
> **I want** 一键切到阅读模式看完整成品
> **So that** 我可以在评审 / 交付前确认无编辑残留 UI

**入口**：
- Ctrl+/ 循环
- 命令面板 `VSWord 视图模式: 切换阅读模式`
- 工具栏按钮「阅读模式」

**视觉反馈**：
- shell attr `data-mode="reading"`
- Milkdown ctx `editable = () => false`（**本 PRD 新增**——现状仅 CSS 隐藏 UI，内容仍可改）
- caret 隐藏；slash / block handle / math editor / mermaid editor 全隐藏（现状已实现）
- 工具栏 focus/typewriter 按钮**保持可用**（可与 reading 叠加）

**退出条件**：Ctrl+/ 循环 / 命令 / 按钮

### 2.3 US-3 专注模式（3.7b.3）

> **As a** 中文写作者
> **I want** 打开专注模式后当前段落亮、其余段落淡化
> **So that** 我在长文里不被上下文干扰

**入口**：
- 快捷键 `Ctrl+Shift+F`（现状已实现）
- 命令面板 `VSWord 视图模式: 切换专注`
- 工具栏 toggle 按钮「专注」

**视觉反馈**：
- shell attr `data-focus="on"`
- 非活动段落 opacity: 0.35，180ms ease；活动段落 `.vsword-focus-active` 保持 opacity: 1（现状已实现，本 PRD 不动 CSS）

**规则**：
- 与 realtime / reading 叠加（叠加于 source 时视觉禁用但 stored 保留）
- 光标或选区所在段落 = 活动段落

### 2.4 US-4 打字机模式（3.7b.4）

> **As a** 中文写作者
> **I want** 打开打字机模式后当前行始终居中
> **So that** 我不用低头看键盘

**入口**：
- 快捷键 `Ctrl+Shift+T`（现状已实现）
- 命令面板 `VSWord 视图模式: 切换打字机`
- 工具栏 toggle 按钮「打字机」

**视觉反馈**：
- shell attr `data-typewriter="on"`
- 行变化时 coordsAtPos + 8px gate 触发 scroll-into-view 居中（现状已实现）
- MutationObserver 在 toggle 打开瞬间立即居中一次（现状已实现）

## 3. 组合矩阵（规则表 · 锁死）

**核心分类**：
- **mode**（三态互斥）：realtime / reading / source
- **toggles**（独立可叠加）：focus ∈ {on, off}，typewriter ∈ {on, off}

**规则**：

| # | 组合 | mode | focus | typewriter | 行为 | 备注 |
|---|---|---|---|---|---|---|
| M-1 | realtime + focus off + tw off | realtime | off | off | 默认所见即所得 | 首启默认 |
| M-2 | realtime + focus on | realtime | on | off | WYSIWYG 内非活动段落淡化 | US-3 主场景 |
| M-3 | realtime + tw on | realtime | off | on | WYSIWYG 当前行居中 | US-4 主场景 |
| M-4 | realtime + focus on + tw on | realtime | on | on | 两开关叠加（合法） | 允许 |
| M-5 | reading | reading | off/on | off/on | 只读；focus/tw 可叠加 | US-2 |
| M-6 | source | source | 视觉禁用 stored 保留 | 视觉禁用 stored 保留 | textarea 直编；focus/tw 视觉不生效但 preferenceUpdate 时保留 | US-1，切离 source 后 stored 值恢复 |

**冲突处理**：
- 三态互斥由 mode-controller `switchTo()` 天然保证（每次切换单向）
- source 模式下点击 focus/typewriter 按钮：**忽略**（`if (currentMode === 'source') return`——现状已实现）
- 键盘 Ctrl+Shift+F/T 在 source 下：**忽略**（现状已实现 `if (currentMode !== 'source') setToggle(...)`）
- 快捷键冲突：`Ctrl+/` 已被 mode 循环占用；`Ctrl+Shift+F/T` 与 VS Code 内建冲突时通过 `when: activeEditorId == 'vsword.markdown.milkdown'` 上下文约束

## 4. 技术方案（新增 · 复用 · 补齐）

### 4.1 命令化（新增 · 强制项 · 补齐 3.7b.1/2/3/4 全部）

在 host 侧 `milkdownEditorContribution.ts` 用 `registerAction2` 注册以下 Action2，全部 `f1: true`（命令面板可见），全部走 `IVSWordViewModeService`（见 4.2）：

| Action id | 标题 | 快捷键 | 参数 |
|---|---|---|---|
| `vsword.viewMode.cycleMode` | VSWord 视图模式: 循环切换（realtime→reading→source→…） | `Ctrl+/`（当 `activeEditorId == vsword.markdown.milkdown`） | — |
| `vsword.viewMode.toggleSource` | VSWord 视图模式: 切换源码模式 | — | — |
| `vsword.viewMode.toggleReading` | VSWord 视图模式: 切换阅读模式 | — | — |
| `vsword.viewMode.setRealtime` | VSWord 视图模式: 回到实时渲染 | `Escape`（when: `vsword.viewMode.reading || vsword.viewMode.source`，可选） | — |
| `vsword.viewMode.toggleFocus` | VSWord 视图模式: 切换专注 | `Ctrl+Shift+F`（when: `activeEditorId == vsword.markdown.milkdown`） | — |
| `vsword.viewMode.toggleTypewriter` | VSWord 视图模式: 切换打字机 | `Ctrl+Shift+T`（同上） | — |
| `vsword.viewMode.openAsText` | VSWord 视图模式: 用文本编辑器打开当前文件 | — | 复用现有 `openAsText` 通道 |

**双入口一致性约束**：webview 内快捷键（现状已实现）与 host 侧 Action2 快捷键**使用同一 keybinding**，通过 `when` 上下文错开优先级——webview keydown listener 保留（作为 webview 焦点内直响应），host Action2 在 webview 无焦点时兜底。

### 4.2 状态服务化（新增 · 强制项）

**新增文件**：`code-oss/src/vs/workbench/contrib/vsword/browser/milkdownEditor/vswordViewModeService.ts`

```typescript
export interface IVSWordViewModeService {
  readonly _serviceBrand: undefined;
  readonly currentMode: VswordMilkdownMode;
  readonly focus: 'on' | 'off';
  readonly typewriter: 'on' | 'off';
  readonly onDidChangeMode: Event<VswordMilkdownMode>;
  readonly onDidChangeFocus: Event<'on' | 'off'>;
  readonly onDidChangeTypewriter: Event<'on' | 'off'>;

  setMode(mode: VswordMilkdownMode): void;      // 内部会调 storage.store + 广播 event + 广播给 live webview
  toggleFocus(): void;
  toggleTypewriter(): void;
  cycleMode(): void;
}
```

- 实现类 `VSWordViewModeService` 走 `registerSingleton(IVSWordViewModeService, ..., InstantiationType.Delayed)`
- 服务内部：读写 storage（复用 3 个已存在 storage key），维护内存镜像；对每个活跃 `MilkdownEditorInput` 发送 `HostPreferenceResponseMessage` 让 webview 同步
- **contribution 里 `preferenceUpdate` 消息处理器改为**：调 `viewModeService.setMode/setFocus/setTypewriter`（不再直接 `writeMode/writeToggle`），由 service 统一持久化 + 广播（这样 webview 与命令面板双向单一真相源）

**ContextKey**（新增，走 `IContextKeyService`）：
- `vsword.viewMode.realtime` : boolean
- `vsword.viewMode.reading` : boolean
- `vsword.viewMode.source` : boolean
- `vsword.viewMode.focus` : boolean
- `vsword.viewMode.typewriter` : boolean

ContextKey 由 `VSWordViewModeService` 在构造时创建并订阅自己的 event 更新，供 Action2 的 `when` 表达式使用（例如「切走 reading 时才显示 Escape 快捷键」）。

### 4.3 消息协议（复用 · 只补一处）

`milkdownEditorProtocol.ts` **无需新增 message 类型**（`preferenceRequest / preferenceResponse / preferenceUpdate` 已覆盖）。

**唯一新增**：`HostPreferenceResponseMessage` 现有语义是「webview 首帧向 host 拉取」的响应；本 PRD 追加它可由 **host 主动推送**（当命令面板触发切换时，service 广播给所有 live webview）——**协议 shape 完全不变**，只是触发方多了一路。文档在 protocol.ts 顶部注释里补一句。

### 4.4 Milkdown ctx `editable` 切换（新增 · 3.7b.2 唯一功能补齐）

在 `entry.template.js` 里，`onModeChange(nextMode, prevMode)` 回调内根据 `nextMode === 'reading'` 调用 Milkdown editor ctx：

```javascript
editor.ctx.set(editorViewOptionsCtx, {
  editable: () => nextMode !== 'reading',
});
editor.view.updateState(editor.view.state); // 触发 re-render
```

- 当从 reading 退回 realtime，恢复 `editable: () => true`
- source 模式下 Milkdown 视图整体被隐藏（`display: none`），editable 值无关紧要，保持 realtime 时的值即可

### 4.5 UI 组件契约（新增 · 强制项）

**新增文件**：`code-oss/src/vs/workbench/contrib/vsword/browser/milkdownEditor/webview/ui-component.mjs`（或 template）

```javascript
/**
 * @typedef {Object} IMilkdownUIComponent
 * @property {HTMLElement} el
 * @property {(container: HTMLElement) => void} mount
 * @property {() => void} unmount
 * @property {() => void} dispose
 */
```

**第一批 UI 组件契约实施对象**（本 PRD 落地范围）：
1. **`ModeSwitchComponent`**：`#milkdown-mode-switch` 三态按钮组 + focus/typewriter 两个 toggle 按钮（`getMilkdownEditorHtml` 里现有 DOM 剥出来）
2. **`ReadingModeShellComponent`**（**新增**）：阅读模式下的简化 UI 外壳——顶部只留「模式切换 / 退出阅读」按钮，隐藏 slash / block handle 已由 CSS 实现，本组件只负责管理简化 toolbar 的 mount/unmount

原实现里 mode-switch 按钮 DOM 已在 `milkdownEditorHtml.ts` 硬编码，本 PRD 要求：
- HTML 侧保持 DOM 骨架不变（不重排 markup）
- 抽出 `mode-switch.mjs` 模块导出 `createModeSwitchComponent(root, controller)` 返回 `IMilkdownUIComponent`
- `entry.template.js` 里 `const modeSwitchUI = createModeSwitchComponent(...)`；未来 UI 重构时替换实现，`entry.template.js` 只依赖契约

reading / focus / typewriter / source **不各自定义 UI 组件**——除 mode-switch 外，其余可视化都是 CSS + shell attribute，不需要额外组件契约。

### 4.6 与 Round-trip / 其他 NodeView 的隔离

- 阅读模式 `editable=false` 只影响 ProseMirror 输入路径，**不影响** roundtrip session（sessionReady / markdownUpdated 仍照常触发，因为 host 侧 revert / external change 依然要推 reload → parse → sessionReady）
- Mermaid / flow / seq / math NodeView 的 stopEvent + ignoreMutation 契约在 reading 下由 `editable=false` 自动阻断编辑手势，NodeView 内部无需感知模式
- 打字机 recenter 只在 `data-typewriter=on` 下工作，与 outline scroll-into-view 相互独立

## 5. 验收标准（DoD · Given/When/Then）

### AC-1 · 每种模式三入口全通（4 × 3 = 12 断言）

> **Given** 编辑器活跃且 mode 服务已注入
> **When** 用户通过 [快捷键 / 命令面板 / 工具栏按钮] 触发目标模式
> **Then** shell attribute 更新 + service.currentMode|focus|typewriter 更新 + ContextKey 更新 + storage 落盘 + 其他两入口的 aria-pressed 同步

### AC-2 · 组合矩阵 M-1 … M-6 单测覆盖

> **Given** 每条 M-N 组合的起始状态
> **When** 触发目标操作
> **Then** 命中规则表中「行为」列描述，且不触发被禁止的状态（如 source 下 focus 视觉激活）
> **验收**：新增测试文件 `test/node/viewModeMatrix.test.ts` ≥ 6 case，每条矩阵行独立断言 shell attribute + service state + ContextKey 三处一致

### AC-3 · 阅读模式真正只读

> **Given** 用户切到 reading 模式
> **When** 用户在 ProseMirror 内敲任意可打印字符 / 尝试拖拽块 / 打开 slash menu
> **Then** 无字符插入 / 无 DOM 变化 / slash menu 不出现；`editor.ctx.get(editorViewOptionsCtx).editable()` 返回 false

### AC-4 · 源码模式往返

> **Given** realtime 状态，文档含粗体 + 数学 + mermaid
> **When** 切 source → 直接改 textarea 里一个字符 → 切回 realtime
> **Then** WYSIWYG 视图反映改动；roundtrip session 重新 build；无 sourceText 丢失（Gate E 六测无回归）

### AC-5 · 快捷键冲突约束

> **Given** 用户焦点在非 VSWord 编辑器上（例如 Monaco text editor）
> **When** 按 Ctrl+Shift+F
> **Then** VSWord `toggleFocus` **不触发**（因 `when: activeEditorId == vsword.markdown.milkdown` 不成立），走 VS Code 内建行为（如 Find in Files）

### AC-6 · 持久化跨会话

> **Given** 用户设置 mode=reading + focus=on + typewriter=off，关闭窗口
> **When** 重启 VSWord 打开任意 `.md` 文件
> **Then** 3 项 preference 全部恢复；webview `preferenceRequest` 收到的响应字段一致

### AC-7 · Gate 无回归

> - Gate D（tsc 全项目 0 error · `NODE_OPTIONS=--max-old-space-size=8192 tsc --noEmit -p src/tsconfig.json`）
> - Gate E（roundtrip 6 测 252 case 全绿）
> - Gate F（mermaid + flow + sequence + mixed 81 case 全绿）
> - VSWord 单测总数 = 现有基线（≈ 300+）+ 新增 viewModeMatrix ≥ 6 + Action2 单测 ≥ 4，全绿

### AC-8 · UI 组件契约验证

> **Given** `createModeSwitchComponent` 已实现
> **When** 单测里 mount → unmount → dispose
> **Then** container 在 mount 后含 `#milkdown-mode-switch`，unmount 后 detach 但 el 保留，dispose 后无事件监听残留（可通过 sentinel event 断言）

### AC-9 · 中文注释 · 视觉延后

> - 所有新增 ts/mjs 文件顶部注释、Action2 title、命令面板 category 均为中文
> - 不引入新的 CSS 主题变量、颜色、动画（复用现有 `--vscode-*` token）
> - 不改动现有 focus/typewriter 的动画曲线、opacity 数值

## 7. 风险与自救

| 风险 | 触发 | 自救 |

| Ctrl+Shift+F 与 VS Code 「Find in Files」冲突 | 焦点在 webview 时 host Action2 抢不到 | 保留 webview 内 keydown listener 作为主路径；host Action2 作为命令面板/无焦点场景兜底；`when` 表达式限死 activeEditorId |

## 附录 B · 决策记录（本 PRD 一次性锁死，不新开 ADR）

- **D-1 · 源码模式主入口** = webview 内嵌 textarea（沿用现状 `ce03f41f`）；VS Code 原生 text editor 走 `openAsText` 消息作为**次级入口**。理由：现状可用、切换零延迟、不破 roundtrip session。
- **D-2 · 4 模式组合规则** = 「mode 三态互斥；focus/typewriter 独立可叠加于 realtime 或 reading；source 下视觉禁用 stored 保留」。理由：mode-controller 现有实现天然满足，无需重构。
- **D-3 · 快捷键冲突处置** = webview 内 keydown listener 主路径 + host Action2 兜底，共用同一 keybinding 通过 `when` 错开；不新增独立快捷键。
- **D-4 · 消息协议不扩展** = `preferenceRequest/Response/Update` 已足够；host → webview 主动推 preferenceResponse 是新触发方，非新 shape。
- **D-5 · UI 组件契约首批 = ModeSwitchComponent 一个**；reading/focus/typewriter/source 用 CSS + shell attribute 表达，不各自拆 UI 组件。
- **D-6 · 视觉调优全部延后**到 Phase 3 末 UI 重构（AGENTS.md §Phase 3 阶段策略）。
