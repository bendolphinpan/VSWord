## 1. 背景与目标

### 1.1 背景

Phase 3 Milkdown WYSIWYG 已经具备：
- **Round-trip 层**（T-3.8）：byte-for-byte 保真，编辑闭环稳定
- **命令化基础设施**（T-3.7b/c/d）：`registerAction2` + `IStatusbarService` + protocol.ts 三件套已经跑通 5 次以上
- **主题分发链路**（T-3.7d）：`themeChanged` 广播 + 外挂 CSS 注入机制已就绪，导出侧可复用「取当前 markdown theme CSS」的能力

但用户**导出成品文档**的能力还完全缺失：
- 无法把当前 `.md` 导出成**可随手发给别人的 HTML 单文件**
- 无法生成**打印 / 归档用 PDF**
- Typora 用户迁移过来后，找不到 `File → Export → RTF/DOCX/EPUB` 的入口

T-3.8b 补齐**三条链**：**HTML 内置**、**PDF 内置**、**Pandoc 依赖检测式暴露**。三条链共用一套命令化 + 配置 key + 消息协议，为**后续 UI 阶段**（导出按钮 / 侧栏面板）预留稳定接口。

### 1.2 目标（Goals）

- **G1** 用户在命令面板执行 `VSWord: Export as HTML` → 弹 SaveAs → 拿到**单文件可传阅**的 `.html`（内嵌当前主题 CSS + prism 高亮）
- **G2** 用户在命令面板执行 `VSWord: Export as PDF` → 走浏览器 print dialog → 用户"另存为 PDF"落地
- **G3** 本机装了 `pandoc.exe`（或 Open VSX Pandoc 扩展）时，命令面板**额外**出现 `VSWord: Export via Pandoc → DOCX / EPUB / RTF / …`；没装时**命令隐藏**（不弹"请先安装 pandoc"）
- **G4** 三条链共用一套 `vsword.export.*` 命令 ID + `vsword.export.*` 配置 key + `protocol.export.*` 消息前缀，为 Phase 3 收官后的 UI 重构预留接口

### 1.3 非目标（Non-Goals）

以下**严格禁止**在本模块做（AGENTS.md Phase 3 视觉延后 + Master plan M-1=C 决策约束）：

- ⛔ **内置 pandoc 二进制**：安装包体积敏感，Pandoc 走**外部依赖**检测路径
- ⛔ **打印样式微调**（分页断行、页眉页脚、代码块背景色）：留最后 UI 布局阶段
- ⛔ **导出后自动打开文件**：v1 只交付「文件已生成到 xxx」的 notification + Reveal in Explorer action
- ⛔ **批量导出**（多个 `.md` 一次导出成 zip）：v2 特性
- ⛔ **模板系统**（自定义导出模板 / Handlebars）：v2 特性
- ⛔ **静默 headless PDF**（chromium `printToPDF`）：v1 走浏览器 print dialog，b 方案作为 P1 备选（Q-M4=c）
- ⛔ **导出前预览面板**：v2 特性，v1 直接生成
- ⛔ **导出编辑器右上角 button**：Q-M1=a 明确"UI 阶段再加 button"

## 2. 用户故事

**US-1（HTML 分享）**：作为一名写完文章要**发给非 VSWord 用户看**的作者，我按 `Ctrl+Shift+P` → `Export as HTML` → 选保存位置 → 拿到一个**双击就能在浏览器打开、样式一致**的单文件 HTML，微信/邮件里直接发就行。

**US-2（PDF 归档）**：作为一名要把当前笔记**打印装订**的写作者，我执行 `Export as PDF` → 系统弹出浏览器 print dialog → 我选"另存为 PDF"、纸张 A4、缩放 100% → 拿到一份**分页干净、代码不断行**的 PDF。

**US-3（Pandoc 多格式）**：作为一名从 Typora 迁移的用户，我本机装了 pandoc，希望命令面板里能看到 `Export via Pandoc → DOCX`、`→ EPUB`、`→ RTF` 三个选项，一步到位不用切工具。

**US-4（Pandoc 未装静默降级）**：作为一名**没装** pandoc 的普通用户，我打开命令面板搜 "export"，只看到 HTML / PDF 两条，**不被"请安装 pandoc"的 notification 骚扰**。

**US-5（配置项复用）**：作为一名管多个仓库的用户，我在项目级 `.vscode/settings.json` 里配 `"vsword.export.imageMode": "sibling-folder"`，希望**该项目下所有** HTML 导出都走"复制到 `<filename>_files/`"策略，不用每次单选。

**US-6（工作区只读兼容）**：作为一名在只读 workspace（如公司归档 workspace）里工作的用户，我导出时**必然**弹 SaveAs 让我选新位置，不能默认写到当前 `.md` 同目录报权限错。

## 4. 子卡详细规格

### 4.1 T-3.8b.1 — HTML 导出

**目的**：把当前 Milkdown editor 的**渲染结果 + 主题 CSS**打包成单文件 HTML，用户拿到即可分享。

**用户可见行为**：
- 命令 ID：`vsword.export.html`，命令面板标题 `VSWord: Export as HTML`
- 触发后：**弹 SaveAs 对话框**（Q-M6=a），默认文件名 `<当前 md 文件名>.html`、默认位置**同目录**
- 用户确认后：写文件 → 弹 notification `Exported to xxx.html`，带 `Reveal in File Explorer` action
- 图片处理策略由**配置 key** `vsword.export.imageMode` 决定（Q-M2=c）：
  - `data-uri`（**默认**）：图片全部 base64 内嵌，产出单文件
  - `sibling-folder`：图片复制到 `<filename>_files/`，`<img src>` 改成相对路径

**技术契约**（**不写实现细节**，只定契约）：

- **命令 ID**：`vsword.export.html`（`Action2` + `f1: true` + category `VSWord`）
- **配置 key**：
  - `vsword.export.imageMode`：enum `"data-uri" | "sibling-folder"`，默认 `"data-uri"`
  - `vsword.export.outputDir`：string，默认 `""`（空 = 同 `.md` 目录）—— **v1 不暴露给用户**（scope=`application`, hidden），SaveAs 默认位置从这里取
- **消息协议**（`milkdownEditorProtocol.ts` 新增）：
  ```ts
  /** T-3.8b.1 host → webview：请求 webview 生成 HTML snapshot */
  export interface HostExportHtmlRequestMessage {
    readonly type: 'export.html.request';
    readonly requestId: string;
    readonly imageMode: 'data-uri' | 'sibling-folder';
  }
  /** T-3.8b.1 webview → host：返回 HTML 文本 + 图片资源清单 */
  export interface WebviewExportHtmlResponseMessage {
    readonly type: 'export.html.response';
    readonly requestId: string;
    readonly html: string;                    // 完整 <!doctype html>…</html>
    readonly assets?: ReadonlyArray<{
      readonly relativePath: string;          // 'xxx_files/img-01.png'
      readonly base64: string;                // 供 host 落盘
    }>;
  }
  ```
- **HTML 装配骨架**（webview 侧组装、host 侧只落盘）：
  ```html
  <!doctype html>
  <html><head>
    <meta charset="utf-8">
    <title>{filename}</title>
    <style>{当前主题 CSS + prism CSS + minimal reset}</style>
  </head><body data-theme="{currentTheme}">
    {editor DOM innerHTML,去掉工具栏 / gutter / 状态栏残留}
  </body></html>
  ```
- **主题 CSS 来源**（Q-M3=a）：**内联当前 markdown theme**（复用 T-3.7d 已经能取到的 CSS blob）+ prism 高亮 CSS
- **失败路径**：webview 未 ready → 命令置灰（通过 `contextKey` `vsword.milkdown.ready`）
- **无越权**：具体如何遍历 DOM、如何过滤内部节点属性、`data-uri` 大小上限等**留给 dev 拍板**

**DoD**：
- [ ] 命令 `vsword.export.html` 注册 + 命令面板可见
- [ ] 配置 `vsword.export.imageMode` / `vsword.export.outputDir` 注册 + schema 有描述文案
- [ ] `HostExportHtmlRequestMessage` / `WebviewExportHtmlResponseMessage` 加进 `milkdownEditorProtocol.ts`
- [ ] SaveAs 走 `IFileDialogService.showSaveDialog`
- [ ] 单测：
  - `test/node/exportHtmlAssemble.test.ts`（给定 DOM + 主题 CSS + imageMode，输出契约 HTML）
  - `test/node/exportHtmlImageMode.test.ts`（`data-uri` vs `sibling-folder` 两种输出对比）

### 4.2 T-3.8b.2 — PDF 导出

**目的**：让用户拿到 PDF，**尽量少写代码**（Q-M4=c，先走 a：浏览器 print dialog）。

**用户可见行为**：
- 命令 ID：`vsword.export.pdf`，命令面板标题 `VSWord: Export as PDF`
- 触发后：**先在 host 侧生成同 HTML 一样的 snapshot**（复用 .1 的通路，`imageMode` 强制 `data-uri`），写入**临时目录**，再调用 `workbench.action.webview.print`（或等价 API）触发浏览器 print dialog
- 用户在 print dialog 里选"另存为 PDF" → 落盘
- 命令结束后**清理临时 HTML**（`setTimeout` 30s 后 unlink，或注册 lifecycle disposable）

**技术契约**：

- **命令 ID**：`vsword.export.pdf`（`Action2` + `f1: true`）
- **配置 key**：**不新增**，复用 `vsword.export.imageMode`（PDF 强制 `data-uri`，忽略用户配置）
- **消息协议**：**不新增**（复用 .1 的 `export.html.*`）
- **PDF 引擎决策**（Q-M4=c）：v1 走 a（浏览器 print dialog），b（`webview.printToPDF` / puppeteer 静默）作为 **P1 备选**
- **打印样式**：
  - v1 **不写 `@media print` 样式**（Phase 3 视觉延后）
  - `@page { size: A4; margin: 20mm; }` 加进 HTML 头（**唯一例外**，因为不加会导致 Chromium 用超小默认 margin，实用性归零）
- **失败路径**：`workbench.action.webview.print` 命令不存在或抛错 → notification `PDF export requires webview print support`，不 fallback
- **无越权**：临时目录选址（`os.tmpdir` vs `IEnvironmentService.tmpDir`）、清理策略细节由 dev 拍板

**DoD**：
- [ ] 命令 `vsword.export.pdf` 注册 + 命令面板可见
- [ ] 生成的临时 HTML 与 .1 契约一致（复用同一 assemble 函数）
- [ ] `@page` A4 margin 20mm 加进 HTML
- [ ] 单测：
  - `test/node/exportPdfAssemble.test.ts`（断言 HTML 头含 `@page` + `imageMode` 被强制 `data-uri`）
  - `test/node/exportPdfCleanup.test.ts`（临时文件被 disposable 注册）
- [ ] `tsc` 零 error
- [ ] Gate D

### 4.3 T-3.8b.3 — Pandoc 检测

**目的**：本机装了 pandoc 时**动态**暴露多格式导出命令；没装时**静默隐藏**（不打扰用户）。

**用户可见行为**：
- **首次**任一 `vsword.export.*` 命令被查询时（quick-pick 展开时 / f1 面板打开时），**惰性触发** `which pandoc`（Q-M5=c）
- 检测结果 cache 到进程生命周期（无 invalidate，用户装 pandoc 后要 reload window——**PRD 层接受这个限制**，dev 层可选是否加 `pandoc.recheck` 命令）
- 检测成功：命令面板出现三条
  - `VSWord: Export via Pandoc → DOCX` (`vsword.export.pandoc.docx`)
  - `VSWord: Export via Pandoc → EPUB` (`vsword.export.pandoc.epub`)
  - `VSWord: Export via Pandoc → RTF` (`vsword.export.pandoc.rtf`)
- 检测失败：**三条命令根本不注册**（不是注册后 `enablement: false`，而是走**动态注册**——如果动态注册困难，退化为静态注册 + `enablement` context key `vsword.export.pandocAvailable`）
- 触发某格式导出：
  1. 弹 SaveAs（默认后缀跟随格式）
  2. host 侧写临时 `.md`（当前 buffer 内容，Round-trip 保证 byte-for-byte）
  3. 调 `pandoc <tmpMd> -o <userChosenPath> --standalone`
  4. 成功 → notification 带 `Reveal in File Explorer`
  5. 失败 → notification 带 `Show Output`，输出 pandoc stderr

**技术契约**：

- **命令 ID 命名规则**：`vsword.export.pandoc.<format>`（format ∈ 已声明白名单 `docx | epub | rtf`）
- **配置 key**：**不新增**（v1 不暴露 pandoc CLI 额外参数；v2 可加 `vsword.export.pandocExtraArgs`）
- **消息协议**：**不新增**（pandoc 走 host 侧文件 I/O，不经 webview）
- **Context key**：`vsword.export.pandocAvailable`（boolean）；命令 `when` 子句用它
- **检测方法**：
  - Windows：`process.env.PATH` 里查 `pandoc.exe`（用 `IEnvironmentService` 或 node `which` 包）
  - 也检测 Open VSX 有没有 Pandoc 扩展（`IExtensionService.getExtension('...')`）—— **v1 只查 CLI**，扩展路径留 v2
- **失败路径**：
  - pandoc 进程 exit != 0 → 弹 notification `Pandoc export failed`，`Show Output` 打开 `VSWord Export` output channel（新建 channel）
  - pandoc 超时（>30s）→ kill 进程 + 同上 notification
- **安全**：调 pandoc 时**必须**用 `spawn` + args 数组（**不能** shell 拼接），避免用户文件名注入
- **无越权**：pandoc 命令行具体开关（`--standalone` / `--reference-doc` / `--metadata`）由 dev 拍板

**DoD**：
- [ ] Context key `vsword.export.pandocAvailable` 注册 + `IContextKeyService` 更新逻辑
- [ ] 检测函数带 cache（lazy first call）
- [ ] 三条命令 `docx/epub/rtf` 注册且 `when: vsword.export.pandocAvailable`
- [ ] 单测：
  - `test/node/pandocDetect.test.ts`（cache 命中一次 / 未装静默 / 装了返回 path）
  - `test/node/pandocInvoke.test.ts`（args 数组化、stderr 捕获、exit code 处理）
- [ ] `tsc` 零 error

## 5. UI 重构接口预留

对齐 master plan §4a "UI 重构接口预留" 4 条，本模块的落点：

| 预留要求 | 本模块落点 |
|---|---|
| **1. 命令化** | 所有导出入口走 `CommandsRegistry.registerCommand`（`Action2` + `f1: true`）。**禁止**在 webview 里内嵌"导出按钮"；后期 UI 阶段若要加编辑器右上角 button 或状态栏 entry，都只是命令的一层皮。命令 ID 命名空间统一 `vsword.export.*` |
| **2. 状态服务化** | Pandoc 可用性用 `IContextKeyService` 的 `vsword.export.pandocAvailable`，**不**用模块级变量。命令 `when` 子句订阅，webview 不感知。未来若加 `IVswordExportService` 只是加一层壳，key 不变 |

**Should**：
- HTML `sibling-folder` 图片模式（AC-2）
- Pandoc `epub` + `rtf` 两格式
- 只读 workspace SaveAs 路径（AC-4 / QA S4）
- Output channel `VSWord Export`（AC-10）
- `vsword.export.pandocRecheck` 命令（R10 缓解）

- 导出模板系统

## 12. 非功能需求

- **性能**：
  - HTML 导出（含 10 张图 `data-uri`）端到端 ≤ 2s
  - PDF 导出（不含用户在 print dialog 停留时间）临时 HTML 生成 ≤ 1s
  - Pandoc 首次检测 ≤ 500ms（不阻塞 UI，走 async）
- **兼容性**：只用 `IFileDialogService` / `INotificationService` / `IContextKeyService` / `IOutputService` / `ICommandService`（都是长期稳定接口）
- **可测性**：Assemble / 图片模式 / cache / args 数组化全部走纯函数，jsdom 或 node 单测覆盖
- **安全**：
  - pandoc `spawn` 严禁 shell 拼接
  - 导出 HTML 不含用户 workspace 绝对路径（只保留相对路径 / data URI）
- **日志**：pandoc stderr → `VSWord Export` output channel；export 失败 → `ILogService.warn`
- **国际化**：所有用户可见字符串走 `localize()`
- **可访问性**：notification action 文案清晰（`Reveal in File Explorer` / `Show Output` / `Retry`）
