### 1.2 缺口（本模块要补的）

1. **未落**：Typora `.css` 外挂主题加载器。用户放 `.vsword/themes/*.css` 或 `<workspaceFolder>/.vsword/themes/*.css` → 自动扫描 → 注册进主题列表 → 与内置主题**共享同一切换路径**。
2. **未落**：主题状态栏指示器（点击 → 打开 quick-pick，等价 `vsword.selectMarkdownTheme`）。
3. **文档缺失**：3.3.1 内置主题系统没有开发者/用户面向的说明文档。

### 1.3 目标（Goals）

- **G1** 用户把从 Typora 官方主题库下载的 `.css` 丢进 `.vsword/themes/` 就能在 quick-pick / 状态栏里看到并切换。
- **G2** 切换外挂主题**热应用无需重启**，与内置主题走同一条 `themeChanged` 广播链路。
- **G3** 编辑器视图上有**永久可见**的当前主题标记（状态栏 item），点击 = 切换命令。
- **G4** 3.3.1 内置主题系统补一份 audit 文档，方便后续 UI 布局阶段接手。

### 1.4 非目标（Non-Goals）

以下**严格禁止**在本模块做（AGENTS.md Phase 3 视觉延后策略）：

- ⛔ **调整内置 4 主题的具体色值 / 字号 / 间距**（留最后 UI 布局阶段）
- ⛔ **优化 Typora `.css` 选择器到 Milkdown 的映射细节**（`#write` → `#milkdown-root .ProseMirror` 精细替换、字体路径重写、字号覆盖顺序…）
  - 本模块只做**原样注入**（加 scope 前缀 + 相对 URL rebase 到 `webviewUri`），跑通"加载 + 切换 + 卸载"闭环即可
  - **不追求视觉 1:1**，只保证"能加载不崩、切换不残留、卸载干净"
- ⛔ 任何"这个颜色不好看"的视觉微调
- ⛔ 内置主题的**新增**（只做 audit，不加第 5 个）
- ⛔ Typora `.css` 内 `@font-face` 引用外部 CDN 字体的**下载/缓存**（原样保留 URL，交 CSP 与浏览器解决，失败即回退）
- ⛔ Typora `.css` 中 `body.night-mode` 类**深浅色变体自动切换**（v1 一 `.css` 一主题，作者若拆多文件放多份即可）

### 4.2 T-3.7d.2 — Typora `.css` 外挂主题加载器

**目的**：让用户的外挂 `.css` 文件走进 3.3.1 现成的分发链路，**不重造轮子**。

**扫描目录（约定优先）**：

| 优先级 | 路径 | 说明 |
|---|---|---|
| 1 | `<workspaceFolder>/.vsword/themes/*.css` | 项目级（跟随仓库） |
| 2 | 用户全局：`~/.vsword/themes/*.css`（Windows 用 `os.homedir()`） | 用户级 |

- 冲突规则：同名 `.css`（大小写不敏感）**项目级覆盖用户级**。
- 空目录 / 目录不存在 → 静默降级到"只有内置主题"，**不报错、不弹 notification**。
- 非 `.css` 后缀文件忽略。子目录**不递归**（v1 简化）。

**发现流程**：
1. Contribution 初始化时启动一次 `discover()`。
2. 用 `IFileService.watch()` 监听两个目录，`onDidFilesChange` 触发 `rediscover()`（防抖 300 ms）。
3. `discover()` 输出 `ExternalTheme[]`：
   ```ts
   interface ExternalTheme {
     readonly id: string;           // 'ext:<workspace|user>:<slug>'，slug = 文件名去后缀 lowercase
     readonly displayName: string;  // 从 CSS 头注释提取 `Theme Name: XXX`，缺省用 slug
     readonly source: 'workspace' | 'user';
     readonly uri: URI;             // 原始 .css URI
   }
   ```
4. 与内置 id 冲突（如用户放了 `github.css`）：**外挂 id 加 `ext:` 前缀天然不冲突**，白名单单独维护即可。

**注入策略**：
- **不预加载 CSS 内容**。只在被选中时，Contribution 读文件 → 走**已有** CSP scope（`style-src ${cspSource} 'unsafe-inline'` 已放行）→ post 一条新增消息 `themeCssPayload`（见协议扩展）。
- Webview 收到后，把 CSS 文本注入到一个 `<style id="vsword-external-theme">`：
  - 每次覆盖同一个 style tag（切换主题时先清空再写，或直接换 textContent）
  - **加 scope 前缀**：外挂 CSS 里的裸选择器统一 wrap 到 `body[data-theme="<id>"] { … }` 里，避免污染 `default` 主题。实现层可用**最小侵入方案**：直接 `body[data-theme="${id}"] { ${rawCss} }` 让 CSS 天然作用域生效（依赖 CSS 嵌套规则；如宿主浏览器 CSS Nesting 支持不足则用简单字符串前缀化每条 selector — dev 选，二者都能过验收）
  - `#write` 等 Typora 特有 selector **不做映射**（Non-Goal），未匹配即无效，属预期行为
- **图片/字体相对路径**：CSS 里 `url(./fonts/xxx.woff2)` 用 `documentBaseUri` **无法**解析（因为 base 是 .md 目录，不是主题目录）。方案：
  - Contribution 端在读取 CSS 内容时**预处理**：把所有 `url(<relative>)` 用正则替换为 `url(<asWebviewUri(themeDir/relative)>)`
  - 绝对 URL（`http://` / `https://` / `data:`）保持原样

**协议扩展**（`milkdownEditorProtocol.ts` 新增）：

```ts
/** T-3.7d.2 host → webview：切换到外挂主题时先推送 CSS 文本。 */
export interface HostThemeCssPayloadMessage {
  readonly type: 'themeCssPayload';
  readonly themeId: string;      // 'ext:<workspace|user>:<slug>'
  readonly cssText: string;      // 已 rebase 过 url() + 已加 scope 前缀
}
```

- 内置主题**不发** `themeCssPayload`（内联 CSS 已在 HTML 里，webview 只切 `data-theme`）
- 收到 `themeChanged` 时若 `theme` 以 `ext:` 起头，webview **必须先收到过对应 `themeCssPayload`** 才生效；host 侧保证顺序（先 payload 后 changed）

**Contribution 改动**：
- `readEffectiveTheme()` 允许返回外挂 id（放宽 `VswordMilkdownTheme` 联合类型为 `string`，或引入 `ExtendedThemeId = VswordMilkdownTheme | \`ext:${string}\``）
- `broadcastTheme()` 若当前主题是 `ext:*` → 先 post `themeCssPayload` 再 post `themeChanged`
- `isDark` 判定：外挂主题**无从推断**，v1 采用**降级策略**——`ext:*` 时 `isDark = false`（避免 mermaid 走 dark palette 与实际不符）；后续可从 CSS 头注释加 `Prefer-Dark: true` 元数据扩展（Non-Goal for v1）

**扫描目录常量**：新增 `milkdownEditorExternalThemes.ts`，导出：
```ts
export const VSWORD_EXTERNAL_THEMES_DIRNAME = '.vsword/themes';
```

**DoD**：
- [ ] `discover()` 单测（node/mocha）：给定虚拟 fs 目录，返回正确的 `ExternalTheme[]`
- [ ] `url()` rebase 单测：3 种 case（相对 / 绝对 / data URL）
- [ ] scope 包装单测：给定裸 CSS，输出必带 `body[data-theme="ext:…"]` 外层

- [ ] 目录不存在时 `discover()` 返回空数组，不抛
- [ ] `tsc` 零 error

## 5. 验收标准（AC — Given / When / Then）

**AC-1**（Given）workspace 无 `.vsword/themes/` 目录（When）用户执行 `VSWord: Select Markdown Theme`（Then）quick-pick 恰好显示 5 个内置 id，无错误提示。

## 附录 A · 3.3.1 内置主题系统 audit（v1 骨架，T-3.7d.1 补齐）

**决策路径伪代码**：

```
readEffectiveTheme():
  if config.vsword.theme.followWorkbench == true:
    kind = themeService.getColorTheme().type
    isDark = kind ∈ { DARK, HIGH_CONTRAST_DARK }
    key = isDark ? config.vsword.theme.dark : config.vsword.theme.light
    return isValidTheme(config[key]) ? config[key] : (isDark ? 'night' : 'github')
  else:
    stored = storage[vsword.milkdown.lastTheme] // APPLICATION scope
    return isValidTheme(stored) ? stored : 'default'
```

**广播链路**：

```
[user action]         [signal]                        [subscriber]
─────────────────    ─────────────────────           ─────────────
Command palette →    storage.store(lastTheme) →      onDidChangeValue → broadcastTheme()
Settings UI →        onDidChangeConfiguration →      broadcastTheme()
Workbench theme →    themeService.onDidColorTheme →  broadcastTheme() [if followWorkbench]

broadcastTheme():
  theme = readEffectiveTheme()
  isDark = readIsDark()
  for input in liveInputs:
    post(input, { type: 'themeChanged', theme, isDark })
```

**Webview 应用**：
- `data-theme=default` / `""` → 移除属性（回退到 `:root` base tokens）
- `data-theme=<id>` → 设置 body 属性，CSS `body[data-theme="<id>"] { --vsword-* }` 生效
- 广播 `isDark` 给 3 个 NodeView（mermaid / flow / sequence）

**T-3.7d.2 之后新增**：
- `data-theme=ext:*` → 先注入 `<style id="vsword-external-theme">`（内含 scoped raw CSS），再切 body 属性

/*
