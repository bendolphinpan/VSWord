## 0. 目标与非目标

### 0.1 目标（Goals）

- 在 Milkdown webview 内实现 Typora / VS Code 用户熟悉的**查找 + 替换**：
  - `Ctrl+F` → 唤出查找栏 · 输入实时高亮所有匹配 · `Enter` 下一个 / `Shift+Enter` 上一个 · `Esc` 关闭
  - `Ctrl+H` → 唤出查找+替换栏 · `Replace` 单条 · `Replace All` 全部 · `undo` 一次撤销
- 三选项：**区分大小写**（Aa）· **全字匹配**（Ab · word boundary）· **正则**（`.*`）
- 计数显示 `N of M` / `No results` / `Invalid regex`
- 与 `IVSWordViewModeService` 联动：**reading 模式**查找可用、替换禁用；**source 模式**本卡不管（走 Code-OSS 原生 textarea 查找）
- 满足 master plan §UI 重构接口预留 4 项强制要求（命令化 / 状态服务化 / 消息协议 / UI 组件契约）
- Round-trip Gate F 无回归（查找不改 doc；替换后 markdown 字节按替换语义变化，但节点结构、其他区域 byte-for-byte 不动）

### 0.2 非目标（Non-Goals · Phase 3 后置）

- ⛔ **主题 / 视觉调优**（find bar 字号、边框、圆角、悬浮态、动画）——统一放到 Phase 3 末的 UI 布局阶段
- ⛔ **跨文件查找 / 全工作区搜索** —— 走 Code-OSS 原生 Search View（`Ctrl+Shift+F`），不在本卡
- ⛔ **仅在选区内查找 / 替换** —— VS Code 编辑器有此能力，Milkdown 层本 PR 不做
- ⛔ **保留历史查询 / drop-down 历史** —— 每次 open 空白起，不做 storage
- ⛔ **保留大小写替换**（Preserve Case） —— VS Code 编辑器 `AB` 按钮，本 PR 不做
- ⛔ **高亮所有匹配自适应主题** —— 复用 `--vscode-editor-findMatchBackground` / `--vscode-editor-findMatchHighlightBackground` token，不新增色板
- ⛔ **source 模式内的查找替换** —— webview textarea 内走 Code-OSS 原生（该场景下 Milkdown 未挂载）
- ⛔ **webview 原生 find widget 语义** —— 参见 §1.3 现状复核：本 PR 会**拦截 Ctrl+F 优先自建 UI**，shell 原生 widget 不再可达（这是本 PRD 明示的取舍）

### 1.2 关键差别（查找替换 vs 其他 Milkdown 特性）

| 维度 | Mermaid/Flow/Seq NodeView | Wikilink NodeView | TOC NodeView | **查找替换（本 PRD）** |
|---|---|---|---|---|
| 数据源 | 节点自身 attrs | 节点自身 attrs.value | 全 doc heading 树 | **全 doc textContent + 用户 query + 三选项**（跨节点 · 无持久化） |
| 更新触发 | 节点内容变 | 节点内容变 | doc 内 heading 变 | **query 输入 · 选项切换 · doc 事务** |
| UI 位置 | 内嵌节点位 | 内嵌节点位 | 内嵌节点位 | **overlay 悬浮 DOM**（不属 PM doc） |
| Undo 语义 | 各自 tr | 各自 tr | 不改 doc | **单条替换 = 1 tr；Replace All = 1 tr（可一次撤销全部）** |
| 与视图模式耦合 | 无 | 无 | source 模式 CSS 隐藏 | **reading 禁用 replace · source 不参与** |

**关键约束**：Find widget 是**跨节点**能力，必须在 webview 里以 overlay 存在（不是 PM node），同时又要通过 PM 层 Decoration 展示高亮、通过 PM 层 tr 完成替换。UI 层与 PM 层解耦，但共享同一 `IFindState`（query / options / matches / activeIndex）。

### 1.3 webview `enableFindWidget: true` 的现状与取舍

`milkdownEditorContribution.ts:240` 开着 `enableFindWidget: true`，即 VS Code shell 层监听 Ctrl+F 会弹 shell 原生 find widget，对整个 webview DOM 做 text 查找。**但它无法：**

1. 感知 ProseMirror doc / 分不清代码块 vs 正文 vs NodeView placeholder；
2. 触发 replace（shell 原生 widget 是 iframe-level find，没有 replace UI）；
3. 精确做 word boundary / 正则（内建正则有限，且行为不同）；
4. 与我们的 reading-mode / focus-mode / typewriter-mode 联动；
5. 提供 `data-heading-pos` 类的语义跳转。

**取舍（本 PRD 明示）**：**保留 `enableFindWidget: true` 不动**，但 Milkdown webview 内的 ProseMirror keymap 会**先吃 `Ctrl+F` / `Ctrl+H`** → shell 原生 find widget 不再被这两组快捷键唤起。用户仍可通过 shell 命令面板（`Show Find Widget`）手动唤起原生，但这属于逃生通道，非默认路径。

**理由**：
- 自建 widget 可同时驱动 PM Decoration 高亮 + PM tr 替换，用户体验一致；
- Shell 原生 widget 与 Milkdown 高亮语义打架（两套高亮同时出现会视觉噪声）；
- 保留 `enableFindWidget: true` 是为 canvas / mindmap / reactflow 等其他 webview 保持默认；单纯为 Milkdown 关掉会牵扯 contribution 分支判断，成本 > 收益。

## 2. 用户故事 / 交互流

### 2.1 US-1 · 查找

> **As a** 中文写作者
> **I want** `Ctrl+F` 唤出查找栏，输入即高亮全部匹配
> **So that** 长文能秒定位关键词

**流程**：
1. `Ctrl+F` → find bar 顶部粘性下拉出现（宽度撑满编辑器主区，右侧对齐关闭按钮），焦点自动进入 query input
2. 输入 → 实时（debounce ≤ 50ms）全文匹配 → PM Decoration 高亮所有 → 首个匹配设为 active（额外 `.vsword-find-active` class）→ scrollIntoView
3. `Enter` = 下一个（wrap-around 回到第一个）· `Shift+Enter` = 上一个（wrap-around 到最后一个）
4. 三 checkbox：`Aa` / `Ab` / `.*` 切换 → 立即重算 · active 尽量保留在同一 doc 位置附近
5. 匹配数 = 0 → 计数区显示 `No results` · 无高亮
6. `Esc` → 关闭 find bar · 清高亮 · 光标恢复到最后 active 匹配位置

### 2.2 US-2 · 替换

> **As a** 中文写作者
> **I want** `Ctrl+H` 唤出替换栏，可单条或全部替换
> **So that** 修改术语、批量改写不用手工找

**流程**：
1. `Ctrl+H` → find bar 唤起且**同时展开 replace 行**（若 bar 已开且未展开 replace，则展开）
2. `Replace` = 替换 active 匹配 → 光标跳到下一个匹配 → 计数重算
3. `Replace All` = 从后往前遍历匹配 → **合并到单个 tr** → 用户按一次 `Ctrl+Z` 可完全撤销
4. reading 模式：Replace / Replace All 按钮**灰化**且 disabled；`Ctrl+H` 快捷键 no-op（不切模式、不弹 toast，只 preventDefault）

### 2.3 US-3 · 三选项

> **As a** 用户
> **I want** 大小写 / 全字 / 正则可组合
> **So that** 精确匹配想要的位置

**选项**：
- `Aa` = case sensitive · 默认 off（不敏感）
- `Ab` = whole word · 默认 off · 语义 = `\b<query>\b`（正则关时先转义 query 再包 \b · 正则开时用户自己写边界）
- `.*` = regex · 默认 off · 用户 query 直接当正则 · 失败 → input 加 `.vsword-find-invalid` class（红色边框，走已有 `--vscode-inputValidation-errorBorder`）+ 计数区显 `Invalid regex`

**决策 · D-3**：正则引擎用**原生 `RegExp`**，不引 `xregexp` / `re2`。理由：查找场景对 catastrophic backtracking 不敏感（数据量小 · debounce 首匹配 ≤ 100ms 内已能返回，失败 case 用 try/catch 兜住）。

### 2.4 US-4 · 空文档 / 空 query

> **As a** 用户
> **I want** 空文档 + 打开 find / 空 query 时不炸
> **So that** 编辑体验稳定

**行为**：
- 空 query → 无高亮 · 计数区空白 · Enter/Shift+Enter no-op
- 空 doc → 显 `No results` · 无高亮
- 空 query + Replace / Replace All → no-op（不动 doc · 不加 undo entry）

### 2.5 US-5 · 与视图模式的组合

> **As a** 迁移用户
> **I want** find widget 在 reading / focus / typewriter 都能用（除非明确限制）
> **So that** 阅读也能查、专注也能查

**行为**：
- realtime + focus + typewriter：查找 + 替换全开
- reading：查找开 · 替换 disabled（US-2 详解）
- source：本 PR 不管（Milkdown 未挂载 · shell 原生 find 或者未来 T-3.7c.3 后续 PR 单独覆盖）

## 4. 技术方案

### 4.1 命令化（强制项）

在 host 侧新建 `milkdownEditor/find/vswordFindActions.ts`（对齐 `viewMode/vswordViewModeActions.ts` 目录风格）用 `registerAction2` 注册三条 Action：

| Action id | 标题 | 快捷键（when milkdown editor focused） | 参数 |
|---|---|---|---|
| `vsword.find.open` | VSWord 查找: 打开查找栏 | `Ctrl+F`（win/linux）· `Cmd+F`（mac） | — |
| `vsword.find.replace.open` | VSWord 查找: 打开查找并替换栏 | `Ctrl+H`（win/linux）· `Cmd+Alt+F`（mac，对齐 VS Code 编辑器） | — |
| `vsword.find.close` | VSWord 查找: 关闭查找栏 | `Escape`（when `vsword.find.open == true`） | — |

**when 上下文键**（新增 · 走已有 IContextKeyService）：
- `vsword.find.open`（bool · widget 是否可见）
- `vsword.find.replaceVisible`（bool · replace 行是否展开）
- `vsword.find.mode`（string · 复用 `vsword.viewMode` 从 `IVSWordViewModeService`）

**行为**：Action 命中 → host 向活跃 webview 发消息（§4.3）→ webview 内 FindWidgetComponent 相应 open/toggle-replace/close。

**决策 · D-5**：`Ctrl+F/H` **覆盖** Code-OSS 默认（Milkdown webview 内已隔离焦点，无外泄风险，`when: focusedView == 'workbench.editor.vsword.milkdown'` 精确限制）。

### 4.2 状态服务化（webview 内 · 不引 host service）

**决策 · D-2**：查找状态**只驻留 webview**，不新增 host 层 `IFindService`。理由：
- 状态生命周期 = widget open lifecycle · 关闭即销毁；
- 与 host 无任何跨文档共享需求（每份文档各自独立查找）；
- 引入 host service 徒增 message roundtrip 延迟（每次输入都 host↔webview 一趟）。

**webview 内 store**（新建 `webview/find-widget-helpers.template.js`）：

### 4.4 ProseMirror plugin 层 · find-plugin（新增）

**新增文件**：`webview/find-plugin.template.js`

**契约**（Milkdown 5+ / ProseMirror 兼容）：

```javascript
export const findPluginKey = new PluginKey('vsword-find');

export function createFindPlugin(getFindState /* () => IFindState */) {
  return new Plugin({
    key: findPluginKey,
    state: {
      init: () => DecorationSet.empty,
      apply: (tr, oldSet, oldState, newState) => {
        // 触发条件 1：doc 变了 → 重算 matches → 重算 decoration
        // 触发条件 2：用户显式 setMeta({ recompute: true }) → 重算
        // 否则 map old decorations 保持
        const meta = tr.getMeta(findPluginKey);
        if (!meta?.recompute && !tr.docChanged) {
          return oldSet.map(tr.mapping, tr.doc);
        }
        const st = getFindState();
        if (!st.widgetOpen || !st.query || st.invalidRegex) return DecorationSet.empty;
        const matches = computeMatches(newState.doc, st.query, st.options); // 见 §4.5
        return buildDecorationSet(newState.doc, matches, st.activeIndex);
      },
    },
    props: {
      decorations(state) { return this.getState(state); },
    },
  });
}

function buildDecorationSet(doc, matches, activeIndex) {
  const decos = matches.map((m, i) => Decoration.inline(m.from, m.to, {
    class: i === activeIndex ? 'vsword-find-match vsword-find-active' : 'vsword-find-match',
  }));
  return DecorationSet.create(doc, decos);
}
```

**关键约束**：
- `apply` 内 **不能读全局** `FindWidgetComponent` 状态，通过闭包传入 `getFindState`；
- doc 未变 · 用户没显式 recompute → 走 `oldSet.map(tr.mapping, tr.doc)` 保持已算好的 decoration 位置映射（性能兜底）；
- doc 变了 → 重算完整 matches（O(doc.textContent.length + matches × k)）· 单文档 heading ≤ 500 时目标 ≤ 10ms P95。

### 4.5 匹配算法 · computeMatches（新增 · 纯函数）

**位置**：`webview/find-widget-helpers.template.js`

```javascript
/**
 * @param {import('prosemirror-model').Node} doc
 * @param {string} query
 * @param {FindOptions} opts
 * @returns {ReadonlyArray<FindMatch>}
 */
export function computeMatches(doc, query, opts) {
  if (!query) return [];
  let re;
  try {
    const flags = opts.caseSensitive ? 'g' : 'gi';
    let pattern = opts.regex ? query : escapeRegExp(query);
    if (opts.wholeWord && !opts.regex) pattern = `\\b${pattern}\\b`;
    if (opts.wholeWord && opts.regex) pattern = `(?:^|(?<=\\W))${pattern}(?=\\W|$)`;
    re = new RegExp(pattern, flags);
  } catch (_e) {
    return []; // invalidRegex 由 caller 独立探测（try new RegExp 一次）
  }
  const matches = [];
  doc.descendants((node, pos) => {
    if (!node.isText) return true;
    const text = node.text ?? '';
    let m;
    re.lastIndex = 0;
    while ((m = re.exec(text)) !== null) {
      if (m[0].length === 0) { re.lastIndex++; continue; } // 防止空匹配死循环
      matches.push({ from: pos + m.index, to: pos + m.index + m[0].length, text: m[0] });
    }
    return false; // 文本节点不再递归
  });
  return matches;
}

function escapeRegExp(s) {
  return s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}
```

**跨节点约束**：
- Mermaid / flow / seq / math / TOC / wikilink 的 atom NodeView 天然被 `doc.descendants` 跳过（`node.isText === false` 即 return true 继续遍历，但 text 遍历只在真正 text 节点里发生）；atom node 内部无 text 子节点，自动豁免；
- Wikilink 的显示文本会出现在 `text` 节点中 → 会命中（与用户直觉一致）。

### 4.6 事务级重算（复用 §4.4 apply · 无额外 plugin）

find-plugin 的 `apply` 已在 `tr.docChanged` 触发重算 → **不需要独立 appendTransaction plugin**（与 TOC 的差异：TOC 需要跨节点广播给多个 NodeView 实例；find 只有一份 decoration set 挂在 plugin state 内）。

**唯一需要 appendTransaction 的场景**：用户改文档时 active 匹配可能漂移。策略：
- 匹配数减少但 activeIndex 仍有效 → 保持
- 匹配数减少且 activeIndex 越界 → clamp 到 `matches.length - 1`
- 匹配数变 0 → activeIndex = -1

这部分逻辑放到 FindWidgetComponent 的「doc changed listener」（订阅 `EditorView.props.dispatchTransaction` 或用 Milkdown 提供的 hook），**不放** find-plugin.apply（避免 decoration state 与 activeIndex 双向依赖引发循环）。

### 4.7 替换事务（新增 · 纯函数 + FindWidgetComponent 调度）

**位置**：`webview/find-widget-helpers.template.js`

```javascript
/**
 * 单条替换：把 active 匹配的 [from, to] 替换成 replacement text。
 * @returns {number}  new activeIndex（自动指向下一个匹配；-1 表示已到末尾）
 */
export function applyReplaceOne(view, findState) {
  const st = findState;
  if (st.activeIndex < 0 || !st.matches.length) return -1;
  const m = st.matches[st.activeIndex];
  const tr = view.state.tr.replaceWith(m.from, m.to, view.state.schema.text(st.replacement));
  view.dispatch(tr);
  // 替换后不需要计算新 index：doc changed → find-plugin.apply 重算 matches
  // FindWidgetComponent doc-changed listener 会 clamp activeIndex 到下一个位置
  return Math.min(st.activeIndex, st.matches.length - 2); // hint（真实 index 由 listener 定）
}

/**
 * 全部替换：从后往前遍历 matches → 合并到单个 tr（可 undo 一次撤销）
 */
export function applyReplaceAll(view, findState) {
  const st = findState;
  if (!st.matches.length) return;
  let tr = view.state.tr;
  for (let i = st.matches.length - 1; i >= 0; i--) {
    const m = st.matches[i];
    tr = tr.replaceWith(m.from, m.to, view.state.schema.text(st.replacement));
  }
  view.dispatch(tr);
}
```

**关键约束**：
- **反向遍历**避免 offset 漂移（前面替换后后面 from/to 失效）
- **单 tr**保证 undo 一次完成
- `schema.text(replacement)` 只支持 text · 若 replacement 含换行 `\n` → 拆分为多段 + `hardBreak` node（P2 · 本 PR 不做，仅在 fixture 内避免多行 replacement）
- **reading 模式**：调用前先查 mode，disabled 时不 dispatch（UI 层灰化按钮）

### 4.9 键盘绑定 · ProseMirror keymap plugin（新增）

**新增文件**：`webview/find-keymap.template.js`

```javascript
export function createFindKeymap(component /* FindWidgetComponent */) {
  return keymap({
    'Mod-f': () => { component.open({ focusReplace: false }); return true; },
    'Mod-h': () => { component.open({ focusReplace: true  }); return true; },
    Escape:  () => { if (!component.isOpen()) return false; component.close(); return true; },
    Enter:      () => component.isOpen() ? (component.next(), true) : false,

}
```

- Escape：**只在 widget 开时**返回 true · 否则放行给 Milkdown 默认（关 slash-menu / 关自动补全）

### 4.11 与 Round-trip / 其他 NodeView / 视图模式的隔离

- **Round-trip Gate E**：find plugin 只加 decoration，不改 doc；Replace 走标准 `tr.replaceWith` → 与 T-3.8 已有 session build 兼容（现有 6 个 roundtrip 测无回归）

- **T-3.7c.2 outline 面板**：outline 是 host 侧 tree view · 与 find widget 完全解耦

### AC-1 · Ctrl+F 唤出 + 实时高亮

## 8. 风险与自救

| 风险 | 触发 | 自救 |
|---|---|---|
| 大文档匹配数爆炸（10 万+）导致 DecorationSet 构造慢 | 超长文档 + 频繁字如 "的" 查找 | Phase 3 不做 lazy decoration；单文档 heading ≤ 500 场景下用 fixture 断言 P95 ≤ 10ms；> 10 万匹配加 console.warn，不阻塞用户 |
| Replace All 反向遍历 offset 问题 | dev 误用累积 mapping | 单测覆盖 10+ 匹配反向替换后字节一致断言（AC-12 `find-replace.md.expected.after.md`）；文档明示反向遍历 · 直接用 `matches[i]` 原始 from/to |
| 空 regex 匹配（`.*` / `\b`）死循环 | 用户误输入 | `computeMatches` 内 `m[0].length === 0` 时 `re.lastIndex++` 显式推进 |
| shell 原生 find widget 被静默遮蔽引发用户困惑 | 用户以为 Ctrl+F = shell find | Milkdown 编辑器聚焦时 UI 一致；未聚焦时 shell 原生 find 仍可用（点其他 tab 后按 Ctrl+F）；文档明示（README / 命令面板 category 描述） |
| Ctrl+H 与 Code-OSS 默认 replace 快捷键冲突 | Code OSS 默认 `Ctrl+H` = 编辑器 replace | when 条件精确到 `focusedView == 'workbench.editor.vsword.milkdown'` · 只在 Milkdown 得焦时抢占；外部编辑器保持 default |
| reading mode gate 绕过导致 doc 被修改 | dev 忘记在 dispatch 前判 mode | `applyReplaceOne` / `applyReplaceAll` 内部**再判一次** `getFindState().mode === 'reading'` → return · 单测 AC-7 兜底 |
| tsc 循环依赖 | protocol 引入 find message + Action2 引入 viewModeService | 新 message 类型独立 `import type` · Action2 侧不 import runtime · 与 T-3.7c.1 已建立的编译隔离一致 |
| find widget DOM 与 focus mode CSS opacity 冲突 | focus mode 遮罩把 widget 也淡化 | widget 用 `z-index: 999` + `opacity: 1 !important`（视觉延后不做 · 结构上先加 class 通道 · 单测 AC-F-4 覆盖） |
