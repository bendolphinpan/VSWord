## 9. 主代理执行记录（第二轮 · 2026-06-24 晚）

收到你的勾选反馈后定位的两条阻塞 + 修复：

### Bug #1 · 节点点击无响应（§2 第 2 项及以后所有项被卡死的根因）

- 现象：渲染正常，鼠标按下任意节点完全没有 focus 反馈，所有键盘操作（Tab/Enter/Space/Delete/a/s）都没反应。
- 根因：`mindmapHtml.ts` 节点 `<g class="topic">` 的 `mousedown` 监听**没有 `stopPropagation()`**。
  整张 `#mindmap-svg` 在 line 1286 监听了 `mousedown` → 立即 `state.panning = true`，鼠标稍微抖动一下就转成画布平移，事件链先到 `selectNode` 然后立刻被 SVG 抢走焦点 + cursor 切 grabbing，看起来就是"按节点没反应、按一下整个画布抖一下"。
  T-5.8 之前 mindmap 是 read-only 不绑 click，所以这个隐患没暴露；T-5.9 进入 editable 路径后才命中。
- 修复：节点 `mousedown` 增加 `event.stopPropagation()`（dblclick 已有，原本就 ok）。
- 文件：`code-oss/src/vs/workbench/contrib/vsword/browser/mindmapHtml.ts` line 720 附近。

### Bug #2 · `.mm` 默认走文本编辑器、必须右键才能切到 mindmap

- 你的诉求：默认渲染 mindmap，保留切回文本视图的能力。
- 方案：新增 `vswordMindmapAutoOpenContribution` workbench 贡献，监听 `IEditorService.onDidActiveEditorChange`，当任意 `.mm` 资源以 `textFileEditor` 形式被激活时**自动调用** `vsword.actions.openMindmap` 并关掉那条文本 tab。
- 配套：新增显式逃生口命令 `vsword.actions.openMindmapAsText` —— 出现在 Explorer 右键菜单（紧邻 "Open as Mindmap"），点了之后在本 session 内对该资源记忆"用户选择文本"，不再自动切换。
- 为什么不走 `EditorResolverService.registerEditor`：那需要实现 `EditorInput` + 序列化器 + diff 工厂等一整套，超出本次诊断范围。当前方案纯监听 + 公共命令，回退面小、可观测。
- 文件：
  - 新增：`code-oss/src/vs/workbench/contrib/vsword/browser/vswordMindmapAutoOpen.ts`
  - 修改：`code-oss/src/vs/workbench/contrib/vsword/browser/vsword.contribution.ts`（注册贡献）
