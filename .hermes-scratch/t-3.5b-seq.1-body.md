1. **PEG parser 预编译验证（首要）**：
   - 装 `@rokt33r/js-sequence-diagrams@2.0.6-2`（**注意**：官方 npm 包 `js-sequence-diagrams` 已被 npm-security 撤下为 `0.0.1-security` 占位；本 spike 只用 rokt33r fork）
   - 装到 sandbox：`.tmp/seq-spike/`
   - 检查 rokt33r fork 的 chunk 内是否有 `new Function(` 或 `Function(` 调用（PEG parser 特征）
   - 命令：`rg -n 'new Function|Function\(.*return' node_modules/@rokt33r/js-sequence-diagrams/`
   - **决策点**：
     - 若 chunk 里**无** `new Function`（即 fork 已预编译 PEG rules 为普通函数）→ go
     - 若**有** `new Function` → 走 vendor + `pegjs --format globals` 预编译方案（下 step 2）

2. **PEG 预编译兜底方案**（若 step 1 判定为需预编译）：
   - 找到 rokt33r fork 的 PEG grammar 源文件（通常在 `src/` 或 `grammar/*.pegjs`）
   - 用 `pegjs --format globals src/grammar.pegjs output.js` 预编译一份
   - 验证预编译产物是否已消除 `new Function` 调用
   - 记 vendor 化脚本骨架（不需真跑通产品，只出可行性结论）

3. **最小 fixture 渲染 demo**：
   - 建 `.tmp/seq-spike/demo.html`：ESM 引入 sequence + raphael，喂一段 P0 语法（`Actor A` / `A->B: msg` / `A-->B: msg` / `Note over A,B: text`）
   - 浏览器 file:// 打开或 jsdom 跑，验证 SVG 输出
   - 截屏 or SVG dump

4. **bundle 尺寸实测**：
   - esbuild 单独打 sequence chunk（min+gzip）
   - 记录 rokt33r fork Unpacked ≈ 710 KB 的实际打包后瘦身效果
   - **验证 PRD 预估**：sequence chunk ≈ 60-90 KB

5. **CSP 阻塞兜底判定**（对齐 Q2=a 用户拍板）：
   - 用户已选 Q2=a：**vendor + 预编译 PEG**（默认方案）
   - 本 spike 不需再讨论 Q2 其他选项（iframe 沙箱 / 砍 sequence 已由用户排除）
   - 若预编译方案也失败 → 才在 comment 里升级 blocker，请 coordinator 追问用户是否推翻 Q2

6. **raphael 版本冲突消费**（R-3）：
   - flow.1 spike 会给出 raphael@2.3.0 统一方案样本
   - 本 spike 直接消费该方案：raphael 也装 2.3.0
   - 验证 rokt33r fork 声明的 `~2.1.x` 与 2.3.0 API 兼容（跑 P0 fixture 判定）
   - 若不兼容 → 记 patch 方案 or 降级用 2.1.x（但不推翻 flow.1 结论）
