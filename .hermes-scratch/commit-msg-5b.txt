feat(vsword/milkdown): T-3.5c.5b setext heading 保源码

依据 PRD docs/plans/003c-syntax-completion.md（F-20 / AC-10 / §8 T-3.5c.5b）：
原文是 setext（`Title\n====`=h1，`Title\n----`=h2）时，未编辑块回写仍是
setext；用户主动改标题内容或级别时按 remark 默认（不强制写回 setext）。

实施选择：首选路线 · setext-aware serializer 的轻量变体
─────────────────────────────────────
不改 remark-stringify 全局 `setext: false`（避免污染纯 ATX 文档 + 与 PRD
「用户主动改按 remark 默认」一致），在 serialize 产物上做一次针对性后处理：

1. init 阶段：用轻量 remark-parse 抽取原文块级 range，配合 sourceText 从
   块级切片里识别 setext heading，构造 hint 队列（Map<text, hint[]>，FIFO）。
2. serialize 阶段：postProcessSetextHeadings(raw) 扫每一行 `^#{1,2} .+`：
   - hint 命中 + depth 一致 → 改写为 `text\n====...` / `text\n----...`，
     消费一个 hint。
   - hint 命中但 depth 不一致（用户改了级别）→ 保持 ATX。
   - 未命中（用户改了文本 / 新增标题 / hint 耗尽）→ 保持 ATX。
3. 后处理不可变 · 纯字符串输入输出 · 每次 serialize 都从原始 hint 集合
   deep-clone 一份消费队列 → 多次 serialize 场景下互不污染。

不依赖 tracker plugin state · 不依赖 attrs.blockId 注入 · 零 ProseMirror
侵入。R5 降级路径：`disableSetextHeading()` 一行即可关闭后处理回退 ATX。
